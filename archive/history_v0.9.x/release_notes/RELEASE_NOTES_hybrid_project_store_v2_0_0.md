# MyGPR V2.0.0 Hybrid Project Store Phase 1

产品版本仍为 **v0.9.28 beta**；V2.0.0 表示源码存储架构迭代号。

## 已实现

- 新建正式项目默认使用 `mygpr.field_project.v3`。
- 项目级关系、处理分支、产物、导出和审计记录写入 `catalog.sqlite`。
- 每条测线使用独立 `data/lines/<line_id>.h5`，避免整个项目集中到单一巨型 HDF5。
- 原始标准化 B-scan、距离轴、时间轴、深度轴和处理结果采用 HDF5 分块、压缩、shuffle 与 Fletcher32 校验。
- HDF5 数据通过切片代理按需读取；打开测线和视窗预览不再默认展开完整矩阵。
- 处理结果形成显式分支与父子谱系，SQLite 保存分支头和来源关系。
- 空间成果、报告 PDF、交付 ZIP 等外部成果登记到统一导出目录。
- 项目备份前执行 SQLite WAL checkpoint，备份不包含临时 WAL/SHM 文件。
- 测线删除同时处理 HDF5、SQLite 级联和项目回收站。
- 完整性审计可识别缺失容器、缺失数据集、SQLite/HDF5 不一致及未索引 HDF5 处理组。
- 提供 UI 与 CLI 的旧项目显式迁移入口；迁移保留旧文件和迁移前 `project.json` 备份。

## 数据安全边界

- 原始来源文件作为不可变工程证据保留。
- HDF5 中的标准化原始矩阵允许在“先备份、后替换”的方向修正流程中受控更新。
- 项目继续采用单写者策略；SQLite WAL 用于读写隔离，不宣称支持多写者并发。
- 处理产物 HDF5 写入或最终 SQLite 登记失败时执行回滚，不留下可见的半提交版本。

## 本阶段未完成

- RTK/IMU/测高、正式界面标注和 QC 数组尚未全部迁入 HDF5 规范组。
- 旧处理算法执行 NumPy 全数组运算时仍可能通过兼容代理物化完整矩阵。
- 全局/频域算法的两遍分块执行器、halo 融合和中间产物回收属于 Phase 2。
- 多分辨率 B-scan 预览金字塔、磁盘配额和 LRU 缓存回收属于 Phase 2。
