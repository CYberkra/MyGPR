# MyGPR v0.9.28 — 长期维护与生产基础重构

发布日期：2026-07-13

本维护包在 v0.9.28 基础上完成正式工作台去演示化：删除隐式演示工程启动链路、合成项目种子和硬编码项目树，启动后进入真实空状态。

## 核心变化

- 统一项目存储内核：项目会话、单写者锁、只读打开、事务回滚、UTC 时间和强原子写。
- 中央 Schema Registry：顺序迁移、迁移快照、损坏隔离、高版本只读和 Schema 目录治理。
- Durable Job System：持久 journal、资源冲突、依赖、检查点、重试元数据、诊断 ID 和进程型 worker。
- 轻量正式入口：正式启动不再提前导入旧 UI、AutoTune 和研究工具；兼容功能按需加载并登记退出合同。
- 传感器同步合同：时钟域、常量/仿射/分段对齐、设备校准档案、原始顺序诊断、有效性掩膜及误差传播。
- GIS 工程化：规范 EPSG/WKT 与垂直 CRS、内容寻址缓存、栅格 overview、bbox 查询、完整 Shapefile sidecar 和来源身份。
- 报告统一：格式无关 ReportDocument、项目 revision 快照、正式封印、篡改验证和报告生命周期。
- 灾难恢复：外部备份目标、逐文件 SHA-256、ZIP 路径穿越防护、恢复为新项目、只读恢复验证和项目回收站。
- 源文件身份：大文件分块摘要、Merkle root、后台完整 SHA-256；正式报告前强制完成全文件身份确认。
- 算法治理：typed AlgorithmSpec、正式/研究目录分离，移除 WNNM 返回原输入的占位实现。
- 可观测性与发布：结构化日志、诊断上下文、隐私化支持包、pyproject、固定依赖、独立构建环境、SBOM/许可证清单和打包后 EXE 冒烟。
- 长期质量门禁：架构依赖规则、Schema 目录、技术债务棘轮和新基础模块类型检查。
- 发布稳定性：CLI 旧算法通过明确的 `PythonModule.*` 包路径解析，不再依赖 `sys.path`；同机四分片对 Qt/VTK 测试使用跨分片原生单槽锁。

## 兼容策略

- `ProjectService`、旧报告控制器与旧 UI 保留为显式兼容层，但不再拥有独立基础设施实现。
- 新生产代码必须使用统一项目仓储、Schema Registry、Job Manager、报告模型和算法目录。
- 历史兼容模块均登记责任人、退出条件和最晚移除版本，防止永久累积。
