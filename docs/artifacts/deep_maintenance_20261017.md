## 关键故障证据

1. **任务资源泄露**：真实 runner 发布终态后、Future finalizer 运行前，桥接器 forget 删除记录，
   lease 永久无法释放，shutdown 后项目仍不能关闭。回归对完成/失败/取消、forget/prune 和在飞 finalizer 加门闩，
   修复实际资源生命周期，而非通过延迟隐藏竞态。
2. **AutoTune 错用时间尺度**：原始头信息 512ns 的输入未传入后端，时间零点候选按默认 48ns 限制。
   现在 raw/artifact 都携带真实 header 与 trace metadata；不调整算法默认值或搜索阈值。
3. **增量档不可恢复**：保留 1 个档案删除唯一 base；多层链不完整；删除文件在恢复时复活。
   独立复审又覆盖相对目录、大小写改名与取消后仍全量解压的边界，逐项正式 RED 后修正。
4. **传感器来源与提交**：不同目录的同名 sensor.csv 相互覆盖；目录已替换而元数据失败或取消，
   旧记录读到新来源。现在保存原始字节的角色路径，并验证一次性 save/catalog 失败后重开项目的一致性。
   使用真实 backend job 验证提交前取消、已有旧同步版本、提交后迟到取消、lease 释放及普通任务行为。
5. **设置与验收可靠性**：可被解析器读取的设置中，null/非有限数值/坏类型影响恢复；两个写者共享 .tmp 导致冲突；
   序列化异常逃逸。正式 RED 后采用按字段恢复及现有 durable atomic writer。
   原 smoke 已截图成功但未返回 main 或运行 atexit；移除强退后验证完整退出。

## 备份格式与资源代价

新档写 `mygpr.project_backup.v2`；reader 支持 v1/v2，拒绝未知版本。
用未修改的旧 HEAD reader 证明 v1 加删除字段会静默复活文件，因此最终选择 v2，
不把“新读旧”混同为“旧读新”。旧程序会拒绝新 v2 档。
保留一个真实旧 writer 生成的 7.4KB v1 测试档、校验和与来源记录，验证恢复矩阵逐元素一致、
旧 ZIP 不改写及 v2 增量接 v1 基准。只新增对应 schema catalog 条目，项目数据格式和公共 Backend API 不变。

保留 N 个恢复点时，必需祖先一并保留，实体 ZIP 可能多于 N。
`recovery_tested=True` 现在以实际展开并打开恢复项目验证为依据，需要完整快照临时磁盘空间及额外 I/O。
8MiB 分块支持取消，不能据小项目测试宣称多 GB 性能或断电恢复已验收。
