# CDUT 采集 HDF5 兼容记录

日期：2026-10-14。输入是用户提供的 `lineData_streaming.h5`；交接包仅作为格式参考。
原始数据和完整输出保留在本机，不加入 Git。

## 使用

在原有项目测线导入入口直接选择 `.h5` / `.hdf5`，无需转换为 CSV。
`cli_batch.py run` 的 `jobs[].input` 也可以直接指定该文件，算法仍通过 `methods` 显式配置。
兼容的是采集结束后的文件导入，不包含跟随正在写入的文件刷新。

## 数据约定

- `/traces` 为 float32、道×时间采样点；软件归一化为时间采样点×道。
- 根属性 `samples_per_trace` 必须与矩阵列数一致；`store_component` 保留 `real` / `magnitude`，不额外取绝对值或进行 ICZT。
- 时间间隔为 `time_window_ns / samples_per_trace`，时间轴不含时窗右端点。时窗为 0 时保留未知状态和零占位轴，由质检提示缺少时间标定，不套用 250 ns。
- `trace_meta/lon,lat,alt,height` 按道对齐；NaN 在持久化元数据中保存为 null，在处理接口中恢复为 NaN。雷达道不会因缺少定位而被删除。
- 处理接口对应 `longitude,latitude,altitude_m,flight_height_m`。已有显式传感器同步结果优先。
- 文件不包含道间距、频率轴或校准单位。未提供测线长度时，物理长度保持未知（0 占位），界面使用道序号并禁用距离轴；迁移算法要求显式提供实测长度或道间距。不会仅凭 501 点推断频带。
- 预检只读取结构和属性；项目导入按道分块转置至 mmap，支持进度、取消和暂存清理。通用 HDF5 矩阵保持原有方向。
- 元数据序列化在复制前排除矩阵与坐标缓冲，避免分块导入后又将完整 mmap 矩阵复制到内存。
