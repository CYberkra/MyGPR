# 第二轮维护与启动优化

日期：2026-10-17。基于 `codex/maintenance-20261017` 的未提交工作区，保留首轮维护修复。
现有七页界面、算法、数据格式与依赖基线不变，美术重设计继续暂缓。

## 启动方案与实测

完整后端原来在 GUI 模块导入时加载，尽管构造已使用 QThread，导入成本仍在首窗前支付。
现在将运行时导入移入现有初始化 worker，保留真正的 ready/error 门控。
后端完成或失败后才分片构造非首屏页面，避免两项工作同时进行时页面构造变慢。
提前导航仍可通过 `ensure_pages_ready()` 完成页面；项目恢复等待后端与页面接线均就绪。

每组 5 次独立 Python 进程，原生 Windows Qt，使用相同解释器、探针和隔离空设置。
未清 OS 文件缓存；这是源码启动对照，**不代表冷启动或安装版实测**。

| 阶段 | 优化前中位数 | 最终方案中位数 | 变化 |
| --- | ---: | ---: | ---: |
| 主窗口首次 Paint | 3.658 秒 | 3.076 秒 | -15.9% |
| show 后首次 heartbeat | 3.735 秒 | 3.132 秒 | -16.1% |
| 开屏图隐藏 | 3.967 秒 | 3.271 秒 | -17.6% |
| 后端就绪回调完成 | 3.939 秒 | 3.541 秒 | -10.1% |
| 全部页面与接线就绪 | 4.460 秒 | 4.103 秒 | -8.0% |
| show 至预热结束的最大 heartbeat 间隔 | 244 毫秒 | 214 毫秒 | -12.2% |

Heartbeat 反映事件循环派发，不等同于人工交互或实际屏幕呈现延迟。
全部样本保留，包含 Windows 窗口构造尖峰；最终组最大间隔约 294 毫秒，
仍高于基线组最差约 269 毫秒，因此不宣称消除了所有启动卡顿或保证尾部延迟。
两边均 5/5 正常关闭、进程退出 0，无占位页。

曾对比“非首屏模块延后导入”和“只移后端导入但保持并发预热”两个候选。
它们虽然改善首屏中位数，预热最大 heartbeat 间隔却稳定增至 400 毫秒以上，未采用。
最终保留既有页面模块导入方式，调整后端导入与页面构造时序。
该受控干预支持并发工作造成争用的判断，但没有直接采样 GIL 或导入锁，不声称证明具体机制。

## 维护修复

- 初始化未结束就关闭：先请求初始化线程退出并等待当前调用返回，再关闭已创建的后端；
  即使成功回包仍在 GUI 队列中也释放实例，迟到成功/失败不再发布，重复关闭幂等。
  关闭可能等待正在执行的有限导入/构造返回，不伪称具有中断任意阻塞初始化的能力。
- 成果解释：打开会话先清旧剖面，成果预览按会话、项目、测线及 `input_artifact_id` 投递；
  原始回包不覆盖成果会话，同测线浏览其他成果也不会替换标注输入。
- 删除当前测线：从仍存在的测线中选择目标，完整执行切线、预览与成果刷新；
  已确认删除后不再次询问放弃旧对象。删除最后一条时清空相关剖面/成果并拒绝迟到原始预览。
