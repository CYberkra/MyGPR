# ADR-006: 受约束的候选提议与试跑选择

## Status

Accepted — 2026-09-16，仅确认决策流程原则，尚未实施。

## Context

自动处理需要根据当前设备的航空探地雷达数据选择阶段、算法、顺序和参数，而不是只调整用户预先选定的单个算法。用户允许推翻旧实现，并在设计访谈 Q4、Q6 中接受“受约束选择”与“模型提出少量候选、实际试跑后自动选优”。

## Decision

采用“模型提议候选处理链 → 检查明确的处理约束 → 少量候选实际执行 → 根据评价结果自动选择”的流程原则。允许跳过不必要的阶段，并在允许的范围内选择顺序；不把所有数据固定到同一条链，也不开放无约束的增益、平滑等重复堆叠。

网络结构、链长度、候选数量、参数范围、具体顺序约束、评价目标及运行时间上限尚未确定，本决策不预先锁定监督学习或强化学习。

## Alternatives

- 单次模型预测后直接执行：省去候选比较，但用户本轮接受以少量额外计算换取试跑比较机会；尚未开展两者效果或耗时对比。
- 固定处理链：实现简单，但不能满足依据数据选择阶段与顺序的目标。
- 无约束任意组链：动作空间更大，但允许无意义重复和评分利用；用户选择受约束方案。

## Consequences

- 训练与推理需描述完整候选链，执行时使用实际算子，而不是只比较网络输出的分数。
- 候选试跑增加计算量，预算需要实测后确定。
- 试跑评分并不自动等于物理正确性。已运行的纯噪声放大反例表明，不能直接将旧增益评分当作目标恢复奖励；新的评价契约仍需明确并验证。
- 用户在 Q5 要求模型不确定时仍自动完成，不弹出不确定性提示或要求人工确认；在 Q10 进一步要求至少实际执行一个算法，不接受空链原样返回。最终可选处理链必须非空，不能用故意设置的零强度参数伪装处理。原始输入仍可用作效果对照，但不是空链形式的最终候选。这不保证每份输入都有改善，也不要求算法为了改变全零等特殊输入而制造信号；真实执行失败必须如实记录。
- 后续 Q14、Q15 将本次范围明确为单条测线使用统一链，重复运行从固定基准数据版本重跑，不在当前处理结果上继续叠加。该选择降低分段拼接与训练/使用输入分布漂移的风险，但暂不提供区段独立组链能力。
