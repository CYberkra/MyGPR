# AutoTune gprMax Pipe Demo Report

## Experiment Purpose

This report records the first usable MyGPR evidence chain for a controlled
gprMax pipe/cylinder scene:

```text
gprMax forward model -> MyGPR dataset contract -> AutoTune comparison
-> gprMax truth metrics -> Evidence bundle -> comparison_report.md
```

The goal is not to claim field-data generalization yet. The current result
shows that MyGPR can run a reproducible **truth-validated AutoTune** experiment
on a known gprMax target, then export metrics and B-scan evidence suitable for
group-meeting discussion and a paper-methods draft.

## Method Boundary

This is **truth-validated AutoTune**, not **truth-guided AutoTune**.

The gprMax `ground_truth.yaml` is used after processing to validate the manual
and AutoTune branches. It is not used as an input to the AutoTune search for the
same run. This avoids overstating the result by optimizing and validating with
the same truth labels.

## Ground Truth

The gprMax sidecar uses zero-based closed intervals. MyGPR converts them to
Python half-open intervals internally.

Sidecar ROI:

- target ROI: sample `[760, 882]`, trace `[38, 50]`
- background ROI: sample `[760, 882]`, trace `[77, 89]`

MyGPR ROI:

- target ROI: time `[760, 883)`, trace `[38, 51)`
- background ROI: time `[760, 883)`, trace `[77, 90)`

The target/background ROIs are non-overlapping for the longline scene. This
fixes the first 12-trace smoke problem where the target and background ROIs
fully overlapped.

## Workflows

Three workflows were executed:

1. `dewow`
2. `dewow, subtracting_average_2D, sec_gain`
3. `set_zero_time, dewow, subtracting_average_2D, sec_gain`

The recommended current paper/meeting result is workflow 2. Workflow 3 runs
successfully, but zero-time correction changes the evidence interpretation and
should stay secondary until ROI offset handling is validated more deeply.

## Manual Baseline vs AutoTune Parameters

For the standard workflow:

| Method | Manual baseline | AutoTune |
|---|---|---|
| `dewow` | `{"window": 3}` | `{"window": 14, "_low_energy_guard": true}` |
| `subtracting_average_2D` | `{"ntraces": 3}` | `{"ntraces": 90}` |
| `sec_gain` | `{}` | `{"gain_min": 1.0, "gain_max": 12.0, "power": 2.2}` |

The manual baseline is a current experience/default profile. It is useful as an
engineering baseline, but it should not yet be described as an expert-tuned
human optimum.

## Compact Multi-Scenario Matrix

After the first longline scene was validated, four additional controlled
scenarios were generated from the same gprMax GUI resources:

- `cylinder_depth_shallow_v1`: shallower pipe target.
- `cylinder_depth_deep_v1`: deeper pipe target.
- `layered_medium_pipe_v1`: added a higher-permittivity, higher-conductivity
  layer above the target interval.
- `weak_target_noise_v1`: reduced material contrast for a weaker target
  response. This is not yet a true random-noise scene.

All five datasets passed the MyGPR gprMax dataset contract audit and were run
with the standard workflow:

```text
dewow -> subtracting_average_2D -> sec_gain
```

## Additive Noise Stress Test

The earlier `weak_target_noise_v1` scene was a weak-contrast target, not a true
random-noise scene. A deterministic noise augmentation step was therefore added
to create noisy copies of the validated longline pipe dataset. The augmentation
copies the raw gprMax HDF5 package, injects additive Gaussian noise into
`/rxs/rx1/Ez`, and writes a fresh manifest, `ground_truth.yaml`, metadata, and
README. The original gprMax output is not modified.

Generated noisy datasets:

| Scenario | Target SNR | Actual SNR | Audit |
|---|---:|---:|---|
| `pipe_demo_low_snr_noise_v1` | 3 dB | 3.000 dB | READY |
| `pipe_demo_noise_8db_v1` | 8 dB | 8.000 dB | READY |
| `pipe_demo_noise_15db_v1` | 15 dB | 15.000 dB | READY |

Standard workflow result:

| Scenario | Manual truth_score | AutoTune truth_score | Delta | Manual false_positive | AutoTune false_positive |
|---|---:|---:|---:|---:|---:|
| `pipe_demo_low_snr_noise_v1` | -1.102353 | -1.224633 | -0.122280 | 0.978858 | 1.018470 |
| `pipe_demo_noise_8db_v1` | -1.125794 | -1.270860 | -0.145067 | 0.978855 | 1.020414 |
| `pipe_demo_noise_15db_v1` | -1.037360 | -1.404514 | -0.367154 | 0.978847 | 1.024179 |

This is a negative result, not a positive AutoTune claim. Under global additive
Gaussian noise, the current standard pipeline does not recover a reliable target
hyperbola, and the AutoTune branch is worse than the manual baseline on
truth_score. Adding `wavelet_2d` to the 3 dB case did not fix the issue.

The immediate conclusion is that low-SNR data needs a dedicated noise-aware
AutoTune path. Gain and background removal are not sufficient. Future
experiments should compare denoise methods explicitly and score them by
target-preserving truth metrics instead of relying on generic visual quality.

## Current Conclusion

This longline pipe scene and compact scenario matrix are the first usable MyGPR
paper/meeting evidence for the gprMax AutoTune route.

What it supports:

- MyGPR can read a gprMax `.out` package with manifest and ground truth.
- MyGPR can convert closed gprMax ROI intervals into internal half-open ROIs.
- AutoTune can run without using ground truth as search guidance.
- Truth metrics can quantify target preservation, background reduction, and
  false-positive risk.
- Evidence export produces a readable `comparison_report.md` and bundle.
- On `pipe_demo_longline_v1`, the standard workflow AutoTune branch improves
  truth_score by about `1.798` and reduces false-positive ratio by about `1.524`.
- Across the five-scenario compact matrix, the standard workflow AutoTune branch
  improves truth_score and reduces false-positive ratio in every scenario.
- MyGPR can now create deterministic noisy gprMax derivatives with recorded SNR,
  seed, manifest, and ground truth.

What it does not support yet:

- It does not prove general performance on real UAV-GPR field data.
- It does not yet prove robustness across enough materials, random noise levels,
  or truly diverse geology.
- It does not yet solve low-SNR additive-noise scenes; current noisy stress
  tests are a known failure case.
- It does not prove that the current manual baseline is the best human expert
  baseline.
- It does not validate motion compensation.

## Limitations

- The compact matrix is still small and single-target.
- gprMax target and background ROIs are geometry-derived and still marked
  `roi_review_required`.
- The selected `subtracting_average_2D` background window can cover all traces,
  so future work should consider better background-removal domains for gprMax
  validation.
- Some AutoTune parameter searches report low confidence or boundary-risk flags.
- `set_zero_time` needs more ROI-offset validation before becoming part of the
  main paper result.
- `weak_target_noise_v1` is a low-contrast target scene, not a true stochastic
  noise scene.
- Additive Gaussian noise scenes currently fail the standard AutoTune claim and
  should be treated as stress tests until a noise-aware AutoTune path is built.

## Next Experiment Stage

The next paper task is to move from the compact matrix to a stronger benchmark:

1. Build a noise-aware AutoTune experiment path that compares denoise methods
   on the new 3/8/15 dB additive-noise datasets.
2. Add `cylinder_depth_medium_v1` for a complete shallow/medium/deep depth
   sweep.
3. Add `multi_target_pipe_v1`, including multi-target ground-truth schema and
   metrics support if needed.
4. Add an expert/manual baseline pass so the paper comparison is not only
   AutoTune versus default experience parameters.
5. Keep `set_zero_time` out of the main claim until processed-ROI offset
   semantics are validated.

Each scenario should produce:

- `.in`
- `_merged.out`
- manifest
- `ground_truth.yaml`
- metadata
- audit result
- Evidence bundle
- `comparison_report.md`

Machine learning, Bayesian optimization, and surrogate modeling should remain
out of the current stage. They become reasonable only after this deterministic
multi-scenario evidence contract is stable.
