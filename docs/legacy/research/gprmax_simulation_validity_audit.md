# gprMax Simulation Validity Audit

This note records the GX-001 audit boundary for MyGPR's current gprMax
benchmarks before further AutoTune redesign.

## Current Benchmark Inventory

The committed benchmark currently used by AT-001 is:

- `sample_data/gprmax_benchmarks/cylinder_single_v1/`
- B-scan CSV: `mygpr_bscan.csv`
- scenario metadata: `scenario.json`
- model input sketch: `model.in`
- ground-truth ROI: `ground_truth.json`

`cylinder_single_v1` is explicitly marked as:

```json
"source": {
  "kind": "synthetic_reference",
  "path": null
}
```

The package does not contain a native gprMax `.out` file. Therefore it is a
deterministic smoke/contract fixture, not verified native gprMax forward output.
It can test MyGPR import, stepwise evidence generation, ROI metric plumbing, and
AutoTune reporting. It must not be used as native gprMax proof in a paper claim.

Native gprMax validation packages should instead contain a manifest that points
to a real `.out` or `_merged.out`, the exact `.in` used to run the model, and a
producer-side `ground_truth.yaml`.

## What Native gprMax Output Should Contain

A paper-usable gprMax package should preserve:

- the original `.in` model file;
- the native `.out` files, or a documented `_merged.out`;
- HDF5 receiver data such as `/rxs/rx1/Ez`;
- gprMax timing metadata such as `dt` and iteration count;
- domain and grid commands: `#domain`, `#dx_dy_dz`, `#time_window`;
- source and receiver commands: `#hertzian_dipole`, `#rx`, `#src_steps`,
  `#rx_steps` for constant-step B-scans;
- a manifest with `primary_out_file`, optional metadata, and
  `ground_truth_file`;
- `ground_truth.yaml` in the producer schema, using zero-based closed ROI
  intervals.

If a benchmark only stores a CSV generated by MyGPR scripts, its timing and data
origin must be treated as synthetic fallback metadata unless it is explicitly
linked back to the original `.out` and `.in`.

## cylinder_single_v1 Audit Conclusion

`cylinder_single_v1` remains useful for:

- quick smoke tests;
- AutoTune runner and Evidence plumbing;
- deterministic regression tests;
- validating that MyGPR truth metrics can consume a known ROI.

It is not sufficient for:

- claiming AutoTune performance on native gprMax simulations;
- paper figures that describe gprMax FDTD output;
- final validation of frequency, PML, domain, or source/receiver geometry.

AT-001 can therefore be described as a stepwise research-validation baseline on
a synthetic reference fixture with MyGPR-style ground truth. It should not be
described as a native gprMax ground-truth experiment.

## PML / Domain / Scan Range Risks

gprMax uses PML absorbing boundaries. When the PML thickness is not explicitly
available, MyGPR's audit assumes the common 10-cell default as a conservative
screening rule.

For `cylinder_single_v1`:

- `domain_m = [0.24, 0.21, 0.002]`
- `dx_dy_dz_m = [0.002, 0.002, 0.002]`
- default 10-cell PML margin is about `0.02 m` on each axis;
- source starts at `x = 0.04 m` and scans to about `x = 0.20 m`;
- receiver starts at `x = 0.08 m` and scans to about `x = 0.24 m`.

The receiver end reaches the upper x boundary in the model sketch. In addition,
the 2D TMz-style z dimension equals one cell, so z-coordinate PML/boundary
checks should be interpreted carefully. These are acceptable warnings for a
toy/smoke fixture, but they are not acceptable as-is for a paper-grade native
simulation.

## Timing Consistency Checks

The audit checks:

- `time_window` from `model.in`;
- `simulation.time_step_s` from `scenario.json`;
- expected `sample_count`;
- whether `time_step_s` is consistent with `time_window / sample_count`;
- whether timing came from a native gprMax `.out` or synthetic scenario
  fallback.

For `cylinder_single_v1`, `time_step_s` comes from scenario metadata, not from a
native `.out`. This is enough for deterministic MyGPR tests but not enough for a
paper claim about gprMax simulation timing.

## Ground Truth ROI Requirements

Before a gprMax package can support paper-grade truth metrics, the ROI must:

- be present in `ground_truth.yaml` or a converted MyGPR truth JSON;
- use documented interval semantics;
- be inside the B-scan shape;
- preserve target and background ROIs separately;
- identify whether background ROIs overlap target ROIs;
- record target geometry and material;
- be traceable to the source model geometry, not only to visual selection after
  processing.

`cylinder_single_v1` contains an inside-B-scan MyGPR ROI, but because the signal
is synthetic reference data, the ROI validates plumbing rather than native FDTD
physics.

## Fixes Required Before Paper Claims

Before MyGPR uses gprMax data for paper claims:

1. Generate a native gprMax package with `.in`, `.out` or `_merged.out`,
   manifest, metadata, and `ground_truth.yaml`.
2. Verify `dt`, sample count, trace count, and time window from the native
   `.out`.
3. Ensure Tx/Rx scan positions and targets remain outside PML and away from
   domain boundaries.
4. Make the scan long enough that the target hyperbola is visible and not
   clipped by the trace range.
5. Validate target and background ROIs against the B-scan shape and model
   geometry.
6. Store paper-candidate Evidence in `MyGPR-Evidence` with the source commit and
   audit report.

Until then, `cylinder_single_v1` should be labelled smoke-only or contract-only
in reports.
