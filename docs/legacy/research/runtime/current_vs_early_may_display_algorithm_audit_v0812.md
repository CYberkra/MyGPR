# MyGPR V0.8.12 — 当前版本与五月初显示/算法差异审计

## 结论

如果对营山测线使用“看起来相同”的处理流程，但当前版本显示效果与五月初结果不同，最可能的原因不是单一 bug，而是以下几类变化叠加：

1. **显示策略变化**：当前版本增加了 display-only 显示配置、处理链路临时查看、滑动/网格对比、对比显示均衡、报告 600 DPI 导出等能力；这些会改变视觉观感，但不一定改变正式数据数组。
2. **处理链路状态变化**：当前版本会保留 Raw 与每一步历史结果，允许临时查看历史步骤。如果导出或观察时处于 display override / 对比模式，视觉结果可能不是正式当前结果。
3. **新算法与默认参数面板变化**：五月初版本通常没有 Trace Median、Trace Savitzky-Golay、处理链路对比篮、结构化 Evidence package 等功能。当前方法注册表和参数展示更完整，默认参数与实际应用步骤更容易被明确记录。
4. **AGC / 背景抑制等幅值敏感步骤本身会显著改变图像观感**：尤其在营山测线这类实测 no-prior 数据上，背景抑制、AGC、显示拉伸和归一化的组合会让同一数据呈现出明显不同的纹理强度。

## 已确认会影响“显示效果”的当前版本变化

### 1. B-scan 主图标题与状态来源变化

当前标题使用当前正式处理阶段，例如 `B-scan / 自动增益控制（AGC）`。如果处于历史步骤临时查看或链路对比，主图标题和状态栏会显示 display-only 状态。这会比早期“当前/原始数据”式标题更精细，但也更容易让用户误把临时查看状态当成正式处理结果。

### 2. 处理链路 Stepper 引入 display override

当前版本支持点击历史步骤临时查看对应 B-scan。该功能不修改正式数据，但主图会切换显示。若用户没有回到当前正式结果，视觉效果会不同。

检查方法：看底部状态是否提示：

- `临时查看`
- `滑动对比`
- `网格对比`
- `差值图`

如果有这些字样，当前主图不是单一正式结果显示。

### 3. 链路对比采用 display-only 视觉均衡

V0.8.11 后，处理链路的滑动对比和网格对比采用每步骤独立稳健对称归一化，并统一显示到 `[-1, 1]`。这解决了 AGC / 背景抑制 / Raw 幅值差异导致一侧变灰的问题。

边界：

- 该均衡只影响对比视图。
- 不改变正式处理结果数组。
- 不应拿对比视图的亮度直接和五月初单图结果比较。

### 4. hover 十字准线 / 选道标记已退役

V0.8.12 中 hover 十字准线已退役；V0.8.11 中持久选道竖线也已退役。现在主图只保留底部坐标读数。这个变化只影响视觉干扰，不影响算法结果。

### 5. 报告图导出与屏幕显示可能不同

当前报告包使用 600 DPI 导出，并记录 display settings。屏幕截图、报告 PNG、滑动对比图和正式当前图可能不是同一种显示上下文。比较五月初图像时应明确比较对象：

- 屏幕主图单图
- 链路对比图
- 报告导出 PNG
- 历史步骤临时查看图

## 已确认会影响“算法结果”的当前版本变化或风险点

### 1. 新增了道向处理算法

当前版本已新增：

- Trace Median / 道向中值滤波
- Trace Savitzky-Golay / 道向 Savitzky-Golay 平滑

若营山测线流程中加入了这些方法，或者替换了早期的尖锐杂波抑制/平滑处理，则结果数组会真实不同。

### 2. Savitzky-Golay derivative 被固定为平滑用途

当前版本为了避免误用，把 Savitzky-Golay 的 derivative 诊断用途收口为平滑算法，不再暴露 derivative。若五月初测试中使用过导数式处理或脚本传参不同，则当前结果会不同。

### 3. Kirchhoff 迁移默认关闭高度/地形校正

当前版本将 Kirchhoff 默认参数改为：

- `hei_cor = 0`
- `topo_cor = 0`

如果五月初版本默认开启高度/地形校正，而当前流程中包含迁移步骤，则结果会不同。若你的营山流程只做背景抑制、AGC、Trace Median 等，则此项无关。

### 4. 处理历史内存策略不会改变当前结果，但会影响可回看步骤

当前版本会按内存预算裁剪历史快照。裁剪只影响历史回看/对比是否可用，不影响当前正式结果。

### 5. no-prior / Evidence / 结构化日志不会改变算法

V0.7.5–V0.7.7 的 Evidence package、结构化日志和 no-prior 记录主要影响可审计性，不应改变 B-scan 数组。

## 针对营山测线差异的排查顺序

### Step 1：确认是否处于正式当前结果

主图底部状态应类似：

`处理链路: Raw -> ... -> 当前方法`

而不是：

- `临时查看`
- `滑动对比`
- `网格对比`
- `差值图`

若处于对比或临时查看，先退出对比并点击当前正式结果。

### Step 2：确认 display-only 设置一致

比较五月初结果时，需要记录并对齐：

- colormap / 色图
- percentile stretch / 拉伸上下限
- normalize / 归一化
- gain display / 显示增益
- axis extent / 距离轴和采样轴
- 是否为 600 DPI 报告导出

### Step 3：确认处理参数完全一致

尤其是：

- 背景抑制：mean / median / SVD / window 设置
- AGC：window samples、增益上限、平滑因子
- Trace Median：window_traces
- Savitzky-Golay：window_traces、polyorder、mode
- 任何 display-only 选项是否误认为处理步骤

### Step 4：导出 Evidence package 对比

当前版本报告包会输出：

- `processing_chain.json`
- `params.json`
- `display_settings.json`
- `runtime_events.json`
- `input_identity.json`

建议用这些文件与五月初记录逐项对比。若五月初没有 sidecar，则至少需要找当时的截图、参数和导出图。

### Step 5：做数组级对比

如果需要判定是“算法输出不同”还是“显示不同”，应保存每一步处理后的数组，比较：

- shape 是否一致
- min / max / mean / std 是否一致
- MAE / RMSE 是否接近 0
- 是否只是显示拉伸不同

如果数组一致但图像不同，问题在显示层；如果数组不同，问题在处理参数或算法实现层。

## 当前判断

在没有五月初源码包、五月初营山处理参数和五月初输出数组的情况下，不能断言当前结果“错了”。但从项目变更看，最可能导致视觉差异的是：

1. 当前版本可能处于链路临时查看或对比视图；
2. 显示拉伸 / 归一化 / 对比视觉均衡与五月初不同；
3. AGC 或背景抑制参数、方法实现或流程顺序不完全一致；
4. 新版把 display-only 与正式处理参数分开记录，五月初可能未区分，导致人工复现时混淆。

建议后续做一个 `YINGSHAN-REPRO-001` 小任务：用同一份营山 CSV，在当前版本中导出每一步数组和 Evidence package；如果能提供五月初导出的图片或旧包，再做逐步图像/数组对齐审计。
