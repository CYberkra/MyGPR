# MyGPR 勘探定位工作台：首期项目管理与入库质控

正常启动入口为项目优先的勘探定位工作台。界面由项目资源树、数据文档区、
上下文检查器和任务/质控/证据抽屉组成。功能标签页不再承担主导航。

首期已接入：

- 正式工程创建、打开、锁定、会话恢复与多测线管理。
- 散装文件和 A-scan 文件夹的临时检查工程。
- 异步正式化，将主数据与侧车复制为只读原始归档；复制完成后单独后台执行
  SHA-256 完整性验证，待验证状态不阻塞浏览。
- 旧采集目录 `manifest.json` 与默认侧车命名发现、人工侧车修正。
- 通用数据结构质控以及 RTK、IMU、高度计实测侧车深度质控。
- `info / warning / error` 分级；未确认警告允许浏览与质控，但需记录现场说明后
  才能进入正式处理，硬错误始终阻断。
- 经典处理窗口显式桥接及处理版本回写。

工程目录契约：

```text
project.mygpr.json
raw/<line_id>/
lines/<line_id>/line.json
qc/<line_id>/latest.json
results/<line_id>/<result_id>/result.json
results/<line_id>/<result_id>/data.npy
interpretations/
workspace/session.json
exports/
```

正式工程内的业务路径全部使用工程根目录相对路径。散装数据快速打开生成临时工程，
仅允许浏览与质控；处理、解释、空间成果和成果报告必须在正式工程中进行。

五个工作区为项目管理、测线处理、目标定位、空间成果和成果报告。项目管理与
入库质控已完整实现；测线处理现已接入原生处理会话、处理链编辑、后台预览与执行、
撤销重做、AutoTune 推荐、人工/自动对比、对比证据导出、推荐流程、结果差值和处理
版本保存/浏览，并提供色图、对称色标、百分位裁剪、共享色标和色标显示等显示层控制。
目标定位支持结构化目标点、界面线和异常范围，并保存为 line-level GeoJSON。空间
综合聚合真实逐道经纬度、地形/高度和目标标注对象；缺少空间元数据的测线明确标记为无
空间定位。成果报告执行成果检查，生成 Markdown 报告、证据索引、空间成果 JSON、
manifest 和 SHA-256 清单。

工程恢复必须显式调用 `ProjectService.recover()`，且仅清理已确认写入进程不再活动的
遗留锁。完整性验证仅为待验证原始文件补充哈希，不覆盖既有 SHA-256 基线；原始文件
发生变化时标记为完整性不匹配并阻断正式处理。
