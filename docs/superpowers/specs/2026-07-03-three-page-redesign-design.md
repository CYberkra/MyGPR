# MyGPR 三页重构型审美升级设计

## 一、总体定位

三页从"很多卡片拼在一起的普通业务页"进化为：**"野外雷达工程作业台"**

### 首屏气质
- 清晰主工作区
- 专业工程/任务身份
- 紧凑稳定布局
- 高信息密度但不混乱

### 不应该是
- 普通互联网管理面板
- 报告预览器
- 碎片工具箱

---

## 二、风格比例

**80% 工程仪表台**
- 强结构
- 强主次
- 高信息效率
- 低装饰

**20% 轻量现代**
- 降低边框分量感
- 更干净的呼吸空间
- 更克制统一的色彩
- 避免沉闷老派工业 UI

---

## 三、三页统一骨架

### 统一阅读序列
```
顶部状态带 → 主工作区 → 次级分析区 → 辅助操作区
```

### 规则
- 顶部：只放当前上下文 + 极少量关键动作
- 中间：必须由一个单一主角区占据
- 侧边/底部：只辅助，不得竞争
- 页面中不出现两个同等分量的"主"区域

---

## 四、统一空间原则

| 区域 | 占比 |
|------|------|
| 主工作区 | 60%–72% |
| 辅助工作区 | 18%–28% |
| 状态/摘要区 | 8%–14% |

---

## 五、空白预算化

### 允许保留的空白
- 主图/主工作区周围一层安全呼吸空间
- 标题到内容的识别间距
- 主要按钮组之间的分离

### 必须清除的空白
- 卡片下半部空空如也
- 固定高度导致浮动图表上下大片空白
- 侧边栏很宽但只有几行内容
- 底栏很厚但表格只有一行提示
- 小控件放在大容器里周围空荡荡

### 原则
> **"以后不允许'为了整齐而留白'，只允许'为了分层而留白'。"**

---

## 六、比例服务任务，不服务控件

### 布局由任务决定
根据：
- 用户盯着最久的区域
- 消耗最多操作时间的区域
- 只是扫一眼的区域

来决定布局，而不是反过来。

> **"不是按钮决定布局，而是任务决定布局。"**

---

## 七、按钮层级最少化

### 三级动作体系
| 级别 | 定义 | 每视觉层 |
|------|------|----------|
| 一级动作 | 页面最重要的单一动作 | 只有一个 |
| 二级动作 | 常见但非主操作 | ≤3 个 |
| 三级动作 | 低频/上下文动作 | 收入更多菜单 |

### 规则
- 每个视觉层只有一个清晰主按钮
- 一行按钮超过 3 个时，分组或折叠
- 小按钮不能承载主要任务

---

## 八、卡片只是容器

### 新原则
- 卡片分隔空间，不通过自身创造视觉重要性
- 主区卡片："轻壳重内容"
- 辅助卡片：紧凑/矮小/明确
- 目标不是"每块是一个模块"，而是"整页是一个工作站"

---

## 九、各页主角

| 页面 | 主角 |
|------|------|
| 项目管理 | 项目状态与任务入口 |
| 测线处理 | B-scan / 处理结果 |
| 空间成果 | 平面图 / 空间关系 |

统一：header 结构、边距节奏、按钮层级、卡片语法、辅助区收敛程度  
不同：主区大小、主图比例、次级信息放置

---

## Part 2：三页统一视觉语言

### 1. 颜色策略："工程蓝灰"

| 角色 | 方向 |
|------|------|
| 主强调色 | 深海蓝青 (#0788A6) |
| 辅助强调色 | 低饱和冰蓝 |
| 基础底色 | 冷白偏灰 |
| 文字色 | 蓝黑，不纯黑 |
| 边框色 | 偏冷浅灰 |

状态色：
- 成功：偏冷工程绿
- 警告：矿物黄/琥珀色
- 错误：铁锈红
- 信息：蓝青系

### 2. 四级标题层级

| 级别 | 用途 | 示例 |
|------|------|------|
| Level A | 页面主上下文 | 当前项目/测线/步骤状态 |
| Level B | 主工作区标题 | B-scan 结果/工程平面图 |
| Level C | 辅助模块标题 | 参数设置/空间辅助/结果摘要 |
| Level D | 字段标签/小说明 | 算法/输入/输出 |

原则：真正显眼的标题只有 1-2 个，辅助标题明显弱于主标题。

### 3. 字体与字重

| 内容 | 字重 |
|------|------|
| 主数字/主状态 | 半粗或中黑，数量要少 |
| 主标题 | 中等偏稳 |
| 正文与标签 | 常规字重 |
| 次要说明 | 更轻、更淡 |

### 4. 卡片策略

- 主区卡片：边框更轻，圆角小而克制，标题栏更薄
- 辅助卡片：更紧凑，更规整
- 阴影：以边框为主叙事，阴影为辅

### 5. 工具栏统一语法

| 位置 | 内容 |
|------|------|
| 左侧 | 当前页最核心动作 |
| 右侧 | 上下文控制/过滤/图层/更多菜单 |

### 6. 状态条统一

"工程上下文带"：
- 比 toolbar 更静
- 比卡片标题更重要
- 像作业抬头，不是提示条
- 只说高价值上下文：项目/测线/步骤/状态/关键摘要

## Part 3：三页逐页重构方案

### A. 项目管理页 → "项目作业启动台"

**骨架**
```
┌──────────────────────────────────────────────────────┐
│ 顶部状态带：当前项目 / 数据状态 / 最近更新 / 快捷动作 │
├──────────────────────────────────────────────────────┤
│ 左：项目主表 + 当前项目详情     │ 右：任务入口 / 项目摘要 │
├──────────────────────────────────────────────────────┤
│ 底部窄区：快速预览 / 最近活动 / 校验提示              │
└──────────────────────────────────────────────────────┘
```

**关键改动**
- 左侧成为绝对主区（项目表 + 项目上下文摘要）
- 右侧压缩成"任务入口 + 项目摘要"，按作业步骤组织
- 底部仅做窄条补充，高度 ≤ 22% 内容高度

**推翻的旧习惯**
1. 多个小卡平均分面积 → 主次分明
2. 项目详情做成厚卡 → 摘要式呈现
3. 右侧堆很多入口按钮 → 按任务步骤组织
4. 底部放很多小预览 → 少而精

---

### B. 测线处理页 → "处理作业台"

**骨架**
```
┌────────────────────────────────────────────────────────────┐
│ 顶部状态带：当前测线 / 流程状态 / 关键指标 / 主动作         │
├────────────────────────────────────────────────────────────┤
│ 左主区：B-scan / 处理结果         │ 右辅区：参数与处理链     │
├────────────────────────────────────────────────────────────┤
│ 底部窄区：处理消息 / 测线概览 / 对比摘要                  │
└────────────────────────────────────────────────────────────┘
```

**关键改动**
- 左主区 B-scan 更高更稳，减少周围壳层
- 右侧从"拥挤表单栏"改"处理控制舱"：上下文→参数→操作，三层分明
- 按钮主次重排：执行本步为一级，对比/保存/批处理为二级，撤销/重置/推荐为三级
- 低频参数折叠，底部瘦身为辅助带

**推翻的旧习惯**
1. 参数栏固定宽度统治整页 → 参数服务主图
2. 动作组固定高度过死 → 以可点击性和呼吸感为优先
3. 所有动作都露在外面 → 低频收纳
4. 主图和辅图平均待遇 → 主图永远优先
5. 底部消息区过高 → 底部瘦身

---

### C. 空间成果页 → "空间判读台"

**骨架**
```
┌────────────────────────────────────────────────────────────┐
│ 顶部状态带：当前项目 / 成果状态 / 图层状态 / 主动作         │
├────────────────────────────────────────────────────────────┤
│ 主地图区（绝对主角）                                        │
├──────────────────────────────────────┬─────────────────────┤
│ 次级分析带：高程剖面 / 关联视图       │ 辅助控制舱：图层/摘要 │
└──────────────────────────────────────┴─────────────────────┘
```

**关键改动**
- 主地图扩大为绝对主角
- 右侧从"并列主区"降级为"辅助控制舱"
- 高程剖面/DEM/关联视图统一到次级分析带
- 工具栏轻量挂靠地图，不侵入主画布
- 空间摘要短而硬

**推翻的旧习惯**
1. 主地图与侧栏长期对抗 → 地图独占主区
2. 次级分析散落不同权重位置 → 统一到次级分析带
3. 侧栏装控制+摘要+说明+图表 → 只保留控制与短摘要
4. 地图周围加很多边框 → 更直接更干净

---

## 三页硬规则

1. 凡是不能提升任务判断效率的空白，都要清掉
2. 凡是和主工作区争空间的辅助区，都要降级
3. 凡是让按钮看起来一样重要的布局，都要重排

---

## 设计口令

**"主区顶满，辅区收紧，操作降噪，信息归位。"**

## 实施记录（2026-07-12）

本设计已在 v0.9.24 主入口完成结构性落地，实施合同标识为 `three_page_redesign.v1`。

### 公共实现

- `EngineeringContextBand`：统一承载工程身份、关键状态、唯一一级动作和不超过三个常驻二级动作。
- `WorkstationSection`：替代等权指标卡和厚重业务卡片，形成“轻壳重内容”的工作站容器。
- 三页统一采用“上下文带 → 唯一主工作区 → 次级分析带 → 辅助操作舱”的阅读序列。
- 截图诊断增加重构专用合同：上下文带比例、主辅区权重、空间地图主导性和三页组件完整性。

### 页面落地

- 项目管理页：测线主表为绝对主区；右侧按建工程、导入数据、数据质检、测线处理组织任务步骤；底部归并为日志、快速预览、检查提示页签。
- 测线处理页：B-scan 为绝对主区；右侧控制舱拆分基础/高级参数；执行当前步骤为唯一一级动作；推荐、撤回、重置和批处理收入“更多”；底部归并为处理链、运行消息、测线概览页签。
- 空间成果页：地图独占主区；高程剖面、DEM 色带、关联视图进入统一分析页签；右下辅助舱仅保留图层和短摘要。

### 自动验收

- 1536×816：布局检查、视觉舒适度检查和重构专用合同均通过。
- 1920×1020：布局检查、视觉舒适度检查和重构专用合同均通过。
- Linux Qt offscreen 环境已完成实际窗口实例化与五页截图。

### 尚未冻结的外部项

Windows 真实桌面 125% DPI、任务栏占用和本机字体渲染仍需执行最终人工冻结验收；该项不改变三页代码结构已完成的结论。
