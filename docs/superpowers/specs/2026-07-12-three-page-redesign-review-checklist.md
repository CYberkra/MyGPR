# MyGPR 三页布局评审清单

## 一、自动检查前置条件

- 捕获尺寸至少包含 1536×816 和 1920×1020。
- `layout_check_report.json` 为通过。
- `visual_check_report.json` 为通过。
- `text_fit_check_report.json` 为通过。
- 五个真实工作页各有且只有一张截图。
- 截图中不得出现重复页面、未加载字体、异常滚动条或 demo 弹窗遮挡。

## 二、三页通用硬检查

### 1. 主次关系

- 第一眼能在 2 秒内识别页面唯一主工作区。
- 主工作区面积占内容区约 60%–72%。
- 不存在两个面积、标题重量和边框重量都接近的“主区”。
- 辅助区不得通过深色底、粗边框或大标题抢过主区。

### 2. 空白

判定为空白过多的条件之一：

- 某卡片可用内容区域连续空置超过 30%。
- 图表有效绘图区小于所属卡片面积的 55%。
- 侧栏宽度超过 300 px，但有效内容不足 5 行或不足 3 个控件。
- 底部区超过页面高度 20%，且只有一行提示或少量记录。

允许的空白仅用于标题识别、主图安全边距和动作组分隔。

### 3. 挤压但不高效

- 文本被省略到无法判断含义。
- 按钮宽度不足以显示核心动作词。
- 参数标签和输入框持续错位。
- 三个以上按钮挤在一行且没有分组。
- 表格列很多，但关键列仍过窄、次要列占据大量宽度。

### 4. 按钮层级

- 每个视觉层只有一个一级动作。
- 常驻二级动作不超过三个。
- 三级动作进入更多菜单、右键菜单或折叠区。
- 一级动作不能使用与普通按钮相同的视觉样式。
- 危险动作不与主动作相邻，也不使用主强调色。

### 5. 图表舒适度

- 测线处理主 B-scan 可视高度不低于 380 px。
- 主图画布至少占所属主卡高度的 66%。
- 图例、坐标轴、标题不遮挡数据。
- 小图不是把大图机械压缩；无法读数时应改为摘要或放大入口。
- 主图周围无明显无意义白带。

## 三、项目管理页专项

- 测线主表是绝对主区。
- 项目详情为摘要，不形成第二张大型主卡。
- 右侧任务入口按“导入—质检—维护—交付”组织，而不是无序按钮堆叠。
- 顶部只显示当前项目、数据健康、最近更新和关键动作。
- 底部活动/预览带高度不超过页面 20%。

## 四、测线处理页专项

- B-scan 占据最长注视时间和最大面积。
- 参数区顺序为：上下文 → 算法 → 参数 → 执行动作。
- “执行当前步骤”是唯一一级动作。
- 推荐、撤回、重置、批量处理不应全部常驻为同权按钮。
- 处理历史足以核对当前链，但不挤压主图。
- 当前测线、Step、矩阵尺寸和执行状态在顶部可快速读取。

## 五、空间成果页专项

- 地图是绝对主角，右侧栏不得与其形成等权双栏。
- 高程剖面/DEM/关联视图统一进入次级分析带。
- 右侧控制舱只保留图层、成果状态、坐标系和短摘要。
- 测线汇总不长期占用主地图高度；优先页签、抽屉或底部分析带。
- 地图工具栏轻量挂靠，不侵入有效画布。

## 六、人工验收记录

每页记录：

- 通过 / 需调整 / 阻断。
- 最明显的主区。
- 最大无效空白位置。
- 最拥挤位置。
- 动作层级问题。
- Windows 125% 与 offscreen 截图差异。
- 调整前后截图文件名。
