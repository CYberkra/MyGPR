# B-scan 机器学习自动处理：设计访谈记录

日期：2026-09-15
状态：Q1—Q17 产品取舍已确认。按用户最新要求，只展开第一阶段计划，后续阶段在实际推进前再细化；当前未开始实施。

## 已确认目标与边界

- 根据 B-scan 数据情况，自动选择处理阶段、具体算法、执行顺序与参数，并执行处理链。
- Q1：先面向当前设备的航空/无人机探地雷达，不以跨设备通用为初始要求。希望抑制地表反射、直达波等非地下目标成分；地下调查对象随项目背景变化，不能把所有水平地下反射统一视为干扰。
- Q2、Q9：以地下目标相对噪声/干扰的可辨认度提高为主要效果目标，同时约束噪声区放大、假反射和真实目标损伤。用户明确选择 Q9 第二种口径，不采用“所有噪声绝对幅值在相同单位下都不得增加”的普遍硬约束。目标与噪声等比例放大不算改善；具体度量和阈值尚未确定。
- Q3、Q11：gprMax 仿真为主要训练来源，允许部分实测参与仪器/噪声统计或模型校准，另留独立实测数据验收。划分必须避免同一物理场景及其派生样本跨校准与最终验收泄漏；比例、标签可用性和校准方式尚未确定。
- Q4：在明确约束下学习阶段、算法、参数与执行顺序，可以跳过不必要的阶段；不是固定一条链，也不允许无约束反复堆叠增益或平滑。
- Q5、Q10：模型不确定时仍自动处理，不弹出不确定性提示、不要求人工确认。用户拒绝“无改善时原样返回”，要求最终处理链至少实际执行一个算法；不能以空链或故意设置零强度参数冒充执行。算法在全零等特殊输入上自然不改变数据，不应为了制造变化而添加伪信号。真实执行失败不能伪装成成功。
- Q6：接受模型提出少量候选，实际试跑比较后自动选择；候选数和可接受运行时间尚未确定。
- Q7：学习决策限定为低频漂移校正、去背景、去噪、增益、滤波五类阶段。零时、高度、轨迹校正归独立前处理；其完成状态与必要输入元数据必须显式核查，不能默认已校正。本次决定没有授权无条件补做所有独立前处理。
- Q8：通用地下结构为默认处理目标，另提供项目级“层状界面”“局部异常”等可选偏好；不逐道或逐线反复询问，不默认每个项目单独训练一套模型。
- Q12：显卡优先，具备可用 GPU 时应利用加速；用户说明使用者都有显卡。不再把“无独显普通电脑也能完成”当成硬性产品要求，但不能据此宣称所有现有算法已有 GPU 实现。
- Q13：接受约 500 采样点×2000 道的单条测线，一次自动选择与处理约 1—3 分钟的规划目标，包含试跑与最终执行、不含导入；实际可达性仍须测量。
- Q14：先做好一条测线，采用整条测线统一处理链，不引入区段各自独立组链与拼接。
- Q15：重复自动处理从固定基准输入重新规划，不在当前处理结果上累积加工；基准可为完成独立前处理的数据，旧成果保留。
- Q16：接受先本机小批验证、测算成本，再按明确预算考虑远程较大显存 GPU。任何付费批次仍须事先确认规模、费用和停止条件，本次回答不是无限预算或直接租机授权。
- Q17：接受对少量实测结果进行人工成对盲评，不要求逐像素标图。校准与最终验收数据及其评价用途分开。
- 引入机器学习，但网络类型、训练标签和训练方式尚未确定。学习对象是如何选择和配置处理链，不是已决定用网络直接生成干净图像。
- 允许完全推翻现有自动处理方案；沉没成本不构成保留旧方案的理由。
- 按逐轮访谈形成共同理解并记录术语与重要决策；得到整体设计确认前不实施、不训练、不启动正演。

“至少执行一步”意味着：即便输入已足够干净，也必须从可执行的非空候选链中作选择。这会限制理论上的最优结果，不能承诺每条数据都优于不处理；验收必须包含已干净输入与无目标场景，区分执行成功和效果改善。

## 已核查事实及证据范围

### 现有自动调参机制

- `mygpr/application/autotune/service.py:91-250`：单方法入口提取数据特征，生成粗筛候选，执行真实算法，细化候选，再按手工评分选优；不是此路径中的神经网络推理。
- `service.py:301-419`：方法比较入口要求候选属于同一阶段（322-325），在同一输入上分别调参，再执行优胜参数并比较。该接口不承担跨阶段顺序搜索。
- `context.py:85-125`：现有特征包括低频能量、横向相关长度、奇异值拐点、浅深部均方根幅值、热点、尖峰和初至统计；标准搜索预算是每方法粗筛 8、细化种子 2、细筛预算 6。不能把这些预算理解为完整处理链候选数。
- `evaluation.py:43-137`：候选经参数约束后调用现有执行器；支持取消、重复参数缓存、失败记录。`service.py:217-249` 另有评分选优、帕累托候选、档位和选择稳定性输出。
- `ui/controllers/processing_controller.py:145-188,242-280`：处理链运行接收已有步骤定义；自动调参命令接收单个方法标识。原始数据与已有处理成果均可作为调参输入。在该命令可见的提交位置，未显式传入数据头或逐道元数据；其他层是否恢复这些信息，需在选定接入方案时继续核实，不能直接宣布整条路径丢失元数据。
- 可评估资产：目录、执行器、约束接口（`ports.py:28-34`）及 `tests/test_autotune_safety_and_evidence.py`、`tests/test_autotune_dependency_injection.py`。本轮未运行这些测试；可复用不代表必须保留旧决策结构。

### 评分风险：已运行只读反例

2026-09-15 以仓库虚拟环境直接调用现有 `_score_gain`，固定随机种子 20260915，输入为 220×81 的纯高斯噪声，没有目标信号：

- 原样输出：得分 `1.6454296353335718`，深部幅度比 1。
- 整体放大两倍：得分 `2.6996389164147994`，深部幅度比 2。
- 两者深浅均衡指标相同，均为 `0.0778153498333091`；没有增加目标信息，得分却提高。

直接运行探针退出码为 0，探针保存在会话文件 `local://autoprocess-score-probe.py`。此前通过持久内核启动子进程的尝试超时，不作为成功证据。

该反例只证明增益评分不能单独作为“目标恢复效果”的学习奖励，不证明整个自动调参系统必然选错。`scoring.py:298-349` 奖励深部对比提升，`quality_metrics.py:396-404` 中该指标为去行中值后的深部标准差，并不识别目标与噪声。

`scoring.py:149-176` 的背景评分也奖励水平相干性下降，并有显著性、边缘与峰值保护项；这是需要覆盖真实水平地层的风险点，而非本轮已经实证的地层误删结论。

### 仿真及实测验收基础

- `sample_data/gprmax_benchmarks/cylinder_single_v1/README.md:11-15` 明确说明，随包 B-scan 是无需运行 gprMax 的合成参考数据，之后才可用实际正演输出替换。目录存在不等于训练用正演语料就绪，也不代表其他目录没有真实仿真。
- 同目录 `model.in` 是半空间单金属圆柱模型，激励为 1.5 GHz Ricker，时间窗 18 ns。不能未经仪器与频段适配便当作无人机实测数据的代表。
- 同目录 `ground_truth.json` 含目标区域与必须保留的双曲线特征，但水平层列表为空；这是单个样例的范围，不覆盖层状反射保真。
- 当前仓库的 `scripts/gprmax_benchmark/` 和 `scripts/auto_tune_validation/` 仅见旧字节码缓存，定向查找未找到 `.py` 源文件。不能把缓存名当成现行可复用脚本；仓库外的研究包未在本轮作全量盘点。
- `tests/fixtures/yingshan_real_v1/` 有真实测线子集、完整文件哈希和清单。`dataset_manifest.json` 明确完整文件属于外部验收资产；例如测线 3 为 501×1813、时间窗 700 ns、道距 0.08537 m。本轮确认清单与子集存在，未读取或重新校验外部完整原始文件。
- `borehole_truth.json` 有五条钻孔/公开雷达解释深度对照，但来源注明是公开基线、不是新算法重拾取结果；文件没有对应道号或像素坐标，不能直接作为逐像素干净标签，也不能把既有误差门槛自动沿用为本次目标。
- 已有文档分层规范见 `docs/developer/TEST_DATA_TIERS.md`；既有 ADR 目录为 `docs/developer/adr/`，后续记录应沿用该目录，不另起一套。

### 输入数据契约与未决边界

- `core/gpr_data_model.py:36-76`：矩阵为二维浮点数据，行是时间/采样点，列是道/距离，另有时间轴和距离轴。
- `core/gpr_data_model.py:415-494`：现有无人机 CSV 导入器从第四列读取幅值，按道重排；要求采样点数、时间窗、道数和道距头信息。它不是在此处将原始复频响转换为时域回波的处理链，仪器前序处理仍需核实。
- 该导入器可读取坐标、高程以及可选的高度/时间戳。缺失可选字段时构造的默认值不等于真实测量，更不证明有有效的逐道姿态或同步信息。
- 不得假设数据已经完成零时、高度或轨迹校正，也不得把这些额外动作默认为本次学习范围。若纳入，必须先具备相应逐道元数据、同步/单位契约，以及带匹配真值的训练和验收数据。
- 即使只做五类阶段，也需定义采样间隔、频率量纲、必要的道距与波形表示；图像缩放后的像素和显示归一化幅值不能不加区分地充当物理输入。

上述为规划前的定向现状核查，不是全仓功能穷举或实测效果验收。子代理服务不可用，事实由主会话直接读取及只读评分探针取得；未修改处理代码、运行全量测试、训练或正演。

此前“达到商业软件八九成”和“核心算法齐全即可交付”的判断没有充分验收依据，不作为本方案前提。算法目录、仿真指标和实测可靠性必须分别举证。

## 决策树

根目标：当前设备航空雷达的单测线自动处理（已确认）。

### 已完成的访谈节点

- Q1、Q7：当前设备与航空场景；模型只决定五类阶段，其他校正独立并显式记录状态。
- Q2、Q9：目标相对噪声/干扰的可辨认度优先，同时约束噪声放大、伪结构与目标损伤。
- Q3、Q11：仿真主训练，允许部分实测校准，最终实测验收独立隔离。
- Q4、Q6：受约束候选提议与少量真实试跑，见 ADR-006。
- Q5、Q10：不确定时也自动执行、不弹确认，最终链至少实际执行一个算法。
- Q8：默认通用地下结构，可选项目目标偏好。
- Q12、Q13：显卡优先，单条约 500×2000 测线以 1—3 分钟为待验证目标。
- Q14、Q15：先做好单线统一链，从固定基准重跑，不分区组链或累积加工当前结果。

### 总体技术路线

[总体技术路线](2026-09-16-ml-autoprocess-architecture-proposal.md)保留多尺度波形编码、候选提议与质量比较的方向，不预先锁定网络初值和全部实现细节。当前仅展开[第一阶段计划](../plans/2026-09-16-ml-autoprocess.md)，后续根据实际结果再规划。

补充实证：本机驱动识别 RTX 3060 Laptop GPU、6 GiB 显存；当前真实样例清单含正负幅值，而相邻采集工程存在输出 ICZT 幅值的 SFCW 支路。二者不应不加表示标记地混训；历史样例对应的实际扫频参数与导出模式仍需核实。证据路径见总体路线中的“已核实的资源与风险”。

### 第四轮结果

- Q16 已确认：本机小批验证并测算成本后，可考虑获明确预算批准的远程 GPU；各付费批次仍单独确认规模、费用和停止条件。
- Q17 已确认：安排少量实测成对人工盲评，不要求逐像素标注；评价用于校准还是最终验收必须预先分开。
- 至此 Q1—Q17 产品取舍已全部回答。具体网络与研究初值以技术提案供整体审阅，不把“产品访谈完成”等同于已批准训练或实现。

### 后续依赖与确认

- Q16 → 仿真与训练试验的预算、设备和分批规模。
- Q17 → 实测校准/验收的人工证据安排；不能把两者数据混用。
- 数据事实门 → 代表性测线的真实采集频率/时间轴、波形表示、前处理来源与可用参考。未核实前不冻结正式仿真语料规格。
- 架构与数据协议复核 → 冻结方法白名单、序列/参数约束、参考标签含义和独立评价指标；禁止把当前手工评分直接当训练真值。
- 整体设计达成共同理解 → 才进入可执行实施计划与获批准的小规模实验，随后按预注册停止规则逐步扩量。
