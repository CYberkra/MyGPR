# MyGPR 永久删除交互设计

2026-11-04 设计，2026-11-05 经用户要求实施。四类永久删除已在工作区接通，回归 CI 和 Windows 原生验收待执行。本版替代此前的回收与恢复提案；对话示例使用虚构数据。

## 方向

Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

2026-11-05 用户补充：只清理 MyGPR 产物和导入副本，最初导入的源数据和传感器源文件必须保留。源文件即使位于项目目录内，也保留原文件及必要父目录；删除项目不能扩大到这些来源文件。

面向反复处理、比较分支、修改解释并输出报告的 GPR 用户。目标是直接清理实际文件，并保持剩余数据和引用关系正确。项目、测线、处理成果、空间成果均直接删除对应文件或容器数据，不经过应用或系统回收站，也不以隐藏备份、延时清空实现删除。这里的永久删除指文件系统删除，不承诺存储介质覆写或安全擦除。

领域对象：原始测线、处理草稿、处理谱系、解释点、空间版本、交付记录。独特交互是删除前直接显示真正受影响的处理分支，而非只显示“确定删除吗”。

沿用已有明暗 design_tokens：面板白/石墨、次级面板灰、正文深灰/浅灰、蓝色交互、琥珀色任务阻塞、红色永久删除。层次由对象名、数量和树形关系表达，正文最多补一条实质后果；不在产品界面展示 `.trash`、事务或 catalog 等实现术语。

避免统一套用警告弹框、给每个移除都加红色按钮、用“已删除”掩盖部分失败。主视觉为影响范围，动作紧贴范围下方；系统中文字体，标题约 18px、正文 14px、辅助身份 12px，4px 间距基数，沿用现有 qfluentwidgets 控件和设计令牌。

## 统一操作合同

| 对象 | 用户看到的动作 | 提交前 | 实际效果 |
| --- | --- | --- | --- |
| B-scan 标签、视图组 | 关闭视图 | 无删除确认 | 重新打开已关闭视图（已有能力） |
| 最近项目记录 | 从最近列表移除 | 直接执行 | 仅移除记录及固定状态，保留项目文件 |
| 处理链步骤 | 移除步骤 | 直接执行 | 编辑待执行草稿；完整步骤撤销栈另行补齐 |
| 解释点 | 删除点；清空当前标注 | 单点/多点直接执行；清空整批作为一笔编辑 | 接入已有会话撤销；清空提示具体点数 |
| 本地 DEM | 卸载地形 | 直接执行 | 重新加载；不承诺删除源文件或回收 |
| 整项目 | 永久删除项目… | 项目名、绝对根路径、MyGPR 产物范围 | 删除项目产物、导入副本、标注、报告和已有回收残留；保留原始源文件及必要父目录；无撤销 |
| 测线 | 永久删除测线… | 项目内原始副本、成果、标注和关联文件 | 直接删除专属文件及登记；共享文件按剩余引用保留或更新；无撤销 |
| 处理成果 | 永久删除成果… | 选中成果及真实依赖后代 | 直接删除对应文件或容器数据并更新谱系；保留兄弟分支；无撤销 |
| 空间成果 | 永久删除版本… | 版本范围，删除后的当前版本选择 | 直接删除版本目录及登记；无撤销 |
| 已结束任务记录 | 清理已结束记录 | 选择明确范围 | 保留任务输出与持久审计；失败记录默认保留供排障 |
| 日志面板 | 清空当前日志 | 直接清当前显示缓冲 | 不混同磁盘日志清理，保留导出能力 |
| 中间成果 | 清理中间成果… | 明确未被输入、分支头或其他保留对象引用的范围 | 直接删除可清理数据；无撤销 |

项目菜单提供“永久删除项目…”。启动页最近项目的对象菜单也提供该动作，与“从最近列表移除”用分隔线分开，让未打开的项目也可删除。路径失效、无法确认项目身份或只读时给出具体原因。删除当前项目成功后回到启动页；删除其他项目不切换当前工作上下文。

整项目确认显示项目名、绝对根路径及内容汇总，最终按钮为“永久删除项目”。一次明确确认即可，不重复弹窗，不默认要求输入名称。只读、任务占用和范围不明确属于阻塞条件，不能用多确认一次代替处理。

删除范围限定在确认的项目内。外部导入源文件、另存到项目外的导出文件不自动追删；目录链接、符号链接及 HDF5 外部链接不能扩大到项目外目标。基于规范化路径、所有权和引用关系判定，不按同名文件猜测。整项目删除包含项目内旧回收残留；删除单项不顺便清空其他历史回收内容。

## 一次确认，只讲实际范围

处理分支示例：标题“永久删除 2 项成果？”，直接列出 `L03 · AGC → 带通滤波` 的依赖树。树形缩进表达后代，不再增加“所选对象”“依赖对象”等重复小标题。只补一句“文件将直接删除，无法撤销”，按钮为“取消 / 永久删除”。

预检对所有选中 ID 求依赖闭包，去重后展示真实总数，不沿用当前 `ids[:1]` 的限制。不允许取消勾选仍依赖父项的后代。已有导出副本是否受影响须依据实际路径说明，不把登记关系变化说成文件被删除。

测线示例：列出测线名称和必要 ID，汇总涉及的项目内数据、处理成果和标注；共享项目坐标文件依据剩余测线更新或保留，不随单测线直接删掉。只有实际受影响时显示“已有报告需要重新生成”。不臆造精确字节数，异步预检未知时省略体积。

空间成果示例：展示名称＋版本，若为当前版本，在确认范围中显示删除后的当前版本选择。整批删除后没有可用版本时明确进入空状态。

右键目标使用右键命中的稳定对象，不能偷偷切换当前处理输入；工具栏和 Delete 键使用当前有焦点列表的选择。文本框中 Delete 保持文本编辑。Esc 取消并回到触发控件，初始焦点放取消；永久删除不绑定全局快捷键。

只读项目、运行任务引用、缺失依赖等阻塞先显示具体原因，如“正在用于任务：L03 成像”。确认前计算范围，确认后执行时在项目锁内再次核验项目身份、任务引用与依赖版本；变化后重新预检，不沿用陈旧确认。整项目删除前释放对应文件句柄、mmap 与预览引用。

## 执行与反馈

1. 预检期间显示“正在计算影响范围”，保留退出入口。
2. 经 controller `run_command` 与 JobBridge 执行。提交后对象原位显示“正在删除”并防重复操作；磁盘删除及登记更新都完成后才移出列表，不能提前显示“已删除”。
3. 单批次完成只显示一条通知，例如“已永久删除 3 项成果”，不提供撤销或恢复。
4. 部分成功显示“已删除 2 项，1 项失败，3 项未执行”，展开明细及仅重试失败/未执行的动作。单对象中途失败须列出已删与残留文件，重试仅作用于残留；登记更新失败也属于未完成，不能当作零变异或完整成功。
5. 取消只停止尚未开始的操作，已删除文件不会回滚。若某阶段不支持取消，就不显示无效取消按钮；进度区别已完成、正在处理和尚未开始。
6. 删除后保持滚动位置，选中邻近仍存在的对象；移走活动成果时切到仍有效的输入或清晰空态。关闭所有被删成果视图并使迟到预览失效，不自动重算，也不跳到不相关页面。

## 直接删除的存储约束

直接删除不可承诺整体回滚。保留操作清单、对象身份及每项进度等必要状态记录，不保留可恢复的数据副本。文件删除、登记更新或进程中断后须能识别未完成操作，标记残留并继续处理，不能把失效数据展示为可用成果。

独立成果文件直接从文件系统移除。共享 HDF5 容器中的成果数据删除后，其他数据须保持可读；删除组不一定缩小容器体积，不能据此声称释放了全部空间。需要整理容器时采用保留剩余数据的安全重写、检查和原子替换；临时写入用于完成存储变更，不作为回收或恢复副本，失败残留必须可识别并清理。释放量只依据实际检查报告。

## 实施顺序

1. 建立所有入口共用的删除预检、确认范围、执行结果模型，覆盖项目身份、任务引用、多选闭包及文件所有权。
2. 接通已有整项目永久删除链路；将成果、测线、空间版本的现有回收链路改为直接删除。同步替换菜单、确认和成功反馈，不新增回收站或文件恢复服务。
3. 补部分失败、进程中断、重试残留以及 UI 上下文清理；处理共享文件和 HDF5 存储整理，再接中间成果清理入口。

验收必须覆盖：取消无变异；文件确实移除且不产生回收副本；单项与批量真实依赖闭包；兄弟分支及共享文件保留；外部路径与链接目标不被追删；只读与任务占用；文件占用和权限失败；中途失败与重启后的残留处理；元数据一致；当前项目删除返回启动页；迟到预览失效；错误反馈、焦点及深浅主题/高 DPI。回归按仓库要求交 CI，原生 Windows 交互单独验收。
