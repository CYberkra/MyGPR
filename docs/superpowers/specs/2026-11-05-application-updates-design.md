# Windows 应用内更新

2026-11-05。用户批准实现首轮更新闭环。保留 PyInstaller onedir 与 Inno Setup；不修改处理算法或自动重算成果。

## 用户流程

设置页“关于”保留版本与检查按钮，提供自动检查开关和稳定版/预览版选择。渠道切换保存后重启生效；WinSparkle 0.9.4 关闭 UI 后不停止所有检查线程，因此不在同一进程重写其全局订阅与回调配置。更新说明、下载进度、取消、稍后与跳过版本由中文原生对话框承载。自动检查最多每天一次；下载和安装由用户选择。源码运行只提供发布页面入口，不运行安装器。

## 实现决定

- 固定 WinSparkle 0.9.4 官方归档与 SHA-256，构建时纳入 x64 DLL 和许可证，不将第三方二进制提交 Git。
- 公钥和订阅地址来自构建产物的 update 配置，不接受用户设置覆盖信任根。必须验证 32 字节 Ed25519 公钥和 HTTPS 地址。缺少配置时明确显示未配置，不静默允许未签名更新。
- 稳定订阅默认指向 GitHub Releases latest 的 appcast.xml；预览订阅需发布者显式提供独立 HTTPS 地址。没有预览地址时禁用该渠道，不把 latest 当预览。
- WinSparkle 负责传输、下载取消、版本比较和 EdDSA 验签。错误时保留当前应用。代码签名证书可选；更新载荷 EdDSA 签名必需。
- can-shutdown 回调来自后台线程。它排队请求 GUI 线程读取实时忙态、后台作业、未保存标注和设置写入能力；有任一阻塞则拒绝安装。允许后冻结窗口交互，防止检查后开始新任务。等待有超时，超时拒绝，不读取后台线程中的 Qt 控件。
- 请求绑定当前代次；超时、停止后到达的旧回调不得冻结或关闭窗口。停止时先唤醒等待回调，再清理原生窗口；C 回调引用保留至进程退出，不能假定 cleanup 等待检查线程。保存设置期间不持有请求锁。
- shutdown-request 只通过信号请求正常 close。关闭取消时恢复交互。不得结束用户任务、强制 kill 或删除项目。Inno AppMutex 保护安装/卸载，关闭 CloseApplications 自动终止路径。
- 按官方时序，shutdown-request 发生在安装器启动之后。关闭取消只能解除界面冻结并提示用户在安装器中取消；不能宣称已取消安装器。错误、下载取消和握手超时均恢复交互。
- 互斥锁只在冻结 Windows 程序创建并保持至进程退出；普通源码与 CI 离屏不持有发布互斥锁。
- 更新配置/public key 随程序；私钥只由发布者持有。提供官方工具封装生成密钥、签名并本地验证安装器、生成按渠道与版本的 appcast，以及可选 Authenticode 构建参数。不得在日志中输出私钥。
- 发布脚本核对私钥导出的公钥、版本、安装包文件名与 SHA-256 是否匹配构建清单。覆盖安装只删除旧清单登记、位于 `_internal`、未被新包使用且内容哈希未改变的文件；拒绝路径越界与 reparse point，不递归清空安装目录。缺少旧清单时保留旧文件。
- 不自动发布 Release、标签或修改总平台子模块。发布者先上传完整安装器/说明/校验，再发布并更新订阅。稳定与预览的版本号分别明确；旧版本首次需手动安装带更新器的新版。

## 验收

GitHub 回归覆盖无配置/非法公钥/非HTTPS/开发版、C ABI 绑定与回调存活、检查取消失败、忙态和脏标注拒绝、GUI 线程握手与超时、成功关闭和关闭取消、设置回放。Windows 定向任务使用固定官方二进制验证真实 EdDSA 签名、篡改拒绝及 DLL API；用小型程序文件夹验证真实 Inno 配方的升级和文件保留。该夹具不代表完整 MyGPR 安装包已验收。

安装包验收工具补充旧安装器→新安装器升级模式，检查版本、设置、项目与用户文件保留。真实旧版升级、断电及安装失败恢复仍需发布前 Windows 安装环境验收，不能用源代码/离屏用例替代。应用回退不承诺逆向迁移已改变的项目格式。

依据：[WinSparkle 回调时序](https://winsparkle.org/c-api/callbacks/)、[订阅格式](https://winsparkle.org/guides/publishing-updates/)、[Inno AppMutex](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm)。
