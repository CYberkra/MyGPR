# 点标记与事件区间实现合同

随 v0.12.0 交付。实现与验收范围见[实施记录](../plans/2026-11-11-marker-event-implementation.md)。
操作入口见[使用指南](../../user/how-to/标记与事件区间.md)。

## 数据与版本

领域对象为 `MarkerRecord`、`EventInterval`、`TraceMapping`、`MarkerProjection`。
记录保存于 `metadata/markers/<line_id>.json`，格式 `mygpr.marker_events.v1`。
来源身份由项目、测线来源版本及采集标记身份派生；新增记录使用 UUID。
源文件替换产生新来源版本，旧标记保留原锚点。名称或道号相同不触发继承。

文件保存采集原字段快照、项目修订、新增记录、区间和解释关联。文档修订号参与过期写入检查。
项目单写者锁保护读改写；隐藏临时文件同步落盘后原子替换。写入失败不关闭编辑草稿。
旧项目只读构建视图，首次明确编辑保存才创建标记文件。只读项目不允许编辑或提交处理。
项目 `timezone` 默认 UTC，接受 IANA 时区；文档快照保留导出时的显示时区。

## 选道与映射

界面道号从 1 开始；内部道锚点从 0 开始；预览中的道段采用左闭右开形式。
设当前输入有 N 道，每个区间解析为道号集合 S。多个区间取并集 U，保留输出 U，剔除输出所有输入道减去 U。
先验证所有区间可用，再合并。因此一个无效区间不会在执行时被悄悄跳过。
输出道号按输入顺序排列、去重，零道输出被拒绝。专用 `trace_range_select` 不调用自动异常检测。

已保存成果的 `params.marker_selection` 包含区间版本快照、输入来源、文档修订号、实际选中道段和输出分段。
修改区间不会改变已有成果；重新执行创建新成果。执行时重新计算预览并比较全部输入条件。

映射数组 `_marker_map_<source_hash>` 和 `_marker_segment` 属于成果逐道元数据，不放入标记 JSON。
`marker_maps` 声明数组所属来源及映射类型。每次处理继承并变换已知来源的横向坐标。
选择类算子保存实际输入列，重采样使用该算子的实际距离坐标，明确保持网格的算子继承坐标。
输入输出道数相等本身不能证明映射有效。未知变换产生无法定位状态。

源位置被删除后不吸附到邻道。插值位置只在有明确定义且同段的坐标间计算。
新增于重采样成果的标记绑定成果本身，不伪造原始道锚点。
图形和 A-scan 显示当前成果位置；插值位置与邻近成果列分开命名。

保留不连续范围时，距离和时间不重新均匀编号。段边界随成果保存与重开。
逐道算子可处理分段结果；需要横向连续输入的算子先拒绝缺口；需要等间距的算子另查实际测距。

## 时间与空间

采集时刻、沿线道序/距离、纵轴双程走时相互独立。所有时间事件使用含时区的 UTC 时间。
标记时间不替代逐道采集时间。逐道时间必须确认 UTC、长度匹配、有限且无回跳，才能用于选道。
暂停采集造成的零匹配时间事件仅保留记录。未闭合事件允许保存但不处理。

空间几何从项目轨迹提取实际采样点；成果区间依据保留片段拆分。
没有有效坐标不画零点，有轨迹缺口不连线。输出只描述沿测线参考范围，不推导面积或深度。
GeoJSON 转换为经度、纬度；投影坐标不能直接标成 WGS84。转换采用明确的 CRS 和 `always_xy=True`。

## UI 与线程

标记胶囊与轴单位共用横轴标题行，并随绘图区变换。列表使用 `QAbstractTableModel` 和筛选代理；放不下的胶囊收进同一行的数量按钮，无 500 条显示截断。
处理和解释工作区共用列表/编辑器逻辑。项目、空间、成果页提供项目级列表。
统一协调器以项目、测线、记录 ID 传播选择。只有明确定位操作改变视野/页面，定位时保留成果版本。
工作线程执行文件 IO；保存成功后通过 Qt 信号刷新。投影坐标转换遵守现有 PROJ 主线程约束。

源记录通过“排除使用”处理。新增记录删除前检查边界与解释引用。
成果永久删除预览显示受影响记录，记录保留失效来源；解释对象有标记引用时要求先解除关联。
CSV/JSON、报告和成果包使用固定快照，GeoJSON 明确不可定位数量。
