# MyGPR 工作台视觉与动效方案

2026-11-25 · 工作台视觉与动效合同。当前桌面有项目、处理、解释、空间信息、设置五个主页，任务记录从底部输出面板进入。审查和实施依据为页面注册、控件信号与交互回归用例。[页面注册](../../../ui/main_window.py) · [现行工作台合同](2026-10-16-workbench-redesign.md)

## 风格定案

采用**清爽、精密的 Fluent 工程工作台**。操作者应先看清当前测线、剖面和选中的对象，再看到能对它做什么。切换成果时，标签下一条细蓝线可以移动，两幅雷达图之间直接换图。这样在比较反射界面时，眼睛可以一直盯着同一个位置。

| 要素 | 设计决定 |
| --- | --- |
| 表面与强调色 | 浅色采用白色内容面与冷灰分区，深色采用石墨灰分层。主操作、活动对象和键盘焦点沿用浅色蓝 `#2563eb`、深色蓝 `#60a5fa`。焦点用轮廓，当前数据标签用 2 个逻辑像素的下划线，键盘焦点和当前项可以分别辨认。 |
| 字体与密度 | 沿用微软雅黑 UI 优先的字体栈，正文 10 pt、分组标题 12 pt、轴刻度与辅助文字 9 pt。沿用 4、8、12、16 的间距档。按钮按下、标签选中、任务文字更新时保持行高，名称较长时优先保留画布空间。 |
| 科学图面 | 雷达振幅沿用数据色图和色阶，解释拾取沿用琥珀色，地图测线沿用系列色。拖放反馈只覆盖正在命中的落区，标记、十字线和坐标读数贴着实际位置。主题和动效设置只作用于显示。 |
| 菜单与弹窗 | 菜单贴着按钮或指针展开，打开就能用方向键选择。参数弹窗出现时直接把焦点交给编辑控件，Esc 返回原入口。切换深浅主题一次换色，剖面继续可读。 |
| 状态反馈 | 运行中的动作在原入口反馈，底部任务行保存可回查的结果。成功、失败、取消均有明确文字。后台完成时，正在查看另一测线的用户保有当前视图和键盘焦点。 |

视觉常量、时长和控件状态按代码与实际操作路径维护。[视觉常量](../../../ui/constants.py) · [主题令牌](../../../ui/design_tokens.py) · [样式表](../../ui-style.md) · [组件状态矩阵](../../design/component-states.md)

## 审查发现与优先级

| 优先级 | 改动前 | 实施要求 |
| --- | --- | --- |
| 优先 · 数据标签 | 标签的 `currentChanged` 启动 160 ms 下划线动画，随后工作区的 `_sync()` 对每组调用 `sync_indicator(animate=False)`，同一次切换就能停掉该动画。[标签](../../../ui/widgets/bscan_source_tabs.py) · [工作区](../../../ui/widgets/bscan_workspace.py) | 把选中和绘图状态立即交给现有切换逻辑。只让目标组的下划线从屏幕当前位置滑向新标签。初显、尺寸变化和布局恢复直接对齐。后台更新同一标签的元数据时，目标几何相同就继续当前动画。 |
| 优先 · 拖放落区 | 每次 `DragMove` 都会让所有分组开始隐藏提示，再让目标组显示。指针即便停留在同一落区内，下一次移动也会重启同一段 100 ms 淡入。[工作区拖放](../../../ui/widgets/bscan_workspace.py) | 首次进入落区时显示提示。同一组内从“右侧拆分”移到“中间合并”时直接换边框和文字，沿标签移动时插入线跟手。只有进入另一组才转移提示；Esc、松手或关闭目标组立即清场。 |
| 优先 · 任务可读性 | 9 pt 任务徽章把固定白字放在状态色上。按实际色值计算，深色“已完成”约 1.85∶1、“运行中”约 2.72∶1，两种主题的“排队／已取消”约 2.54∶1。[任务徽章](../../../ui/widgets/job_widgets.py) · [样式模板](../../../ui/theme_helpers.py) | 任务状态使用成对的文字色、底色，给排队和取消单独选可读的中性色。状态变化时整对立即替换，将连续运动留给进度条。浅深两套的普通文字都以 4.5∶1 为验收目标。[对比度依据](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) |
| 优先 · 任务衔接 | 处理页结束任务时隐藏进度行，下次运行直接归零，两个位置都没有显式停止旧补间。总量未知时任务表仍设为 0–100。当前取消按钮也随“运行中”一直可用。[处理页](../../../ui/pages/processing_page.py) · [进度补间](../../../ui/motion.py) · [任务表](../../../ui/widgets/job_widgets.py) | 同一任务有总量时平滑到最近一次真实进度；总量未知时显示阶段文字。接到取消请求即显示“正在取消…”并抑制重复提交，收到作业终态再显示结果。结束和换任务时停止旧补间，避免下一项首次进度到达前被旧值覆盖。 |
| 其次 · 面板与菜单 | 处理工具栏反向收展时会把当时的中间宽度写作下次展开宽度。右键根菜单、项目菜单使用库默认弹出，键盘子菜单则显式即时打开。系统动画偏好已覆盖多个自绘控件，菜单尚缺统一入口。[处理工具栏](../../../ui/pages/processing_page.py) · [菜单封装](../../../ui/widgets/context_menus.py) · [键盘菜单](../../../ui/widgets/fluent_menu_keyboard.py) | 区分上次稳定展开宽度与本帧宽度，反向时从本帧续接，到最后一次目标后停止。菜单沿用 Fluent 原有呈现，集中处理减少动态效果；鼠标、快捷键进入同一菜单时，命中、焦点和 Esc 行为一致。 |

十月维护记录已覆盖顶部选中块的连续改选、折叠卡裁切、进度条单一动画驱动及窗口销毁。沿用这些行为。该记录的 Windows 数据来自 125% 缩放、小型合成预览和事件循环采样，当前工作树的合成帧率与大测线响应仍需单独测量。[已有维护证据](../../artifacts/motion_maintenance_20261017.md)

## 动效节奏

下表是实施起点，数值指视觉过渡时间。业务状态、输入命中与键盘焦点均在事件到达时更新。

| 场景 | 建议时间 | 使用方式 |
| --- | ---: | --- |
| 主页切换、底部输出收展、解释拾取、十字线、分隔条拖动 | 0 ms | 内容直接就位。项目搜索结果直接更新。空间页先切所选视图，再按既有机制绘制当前地图、切片或三维内容。 |
| 拖放落区首次出现 | 100 ms | 边界和动作含义立即可辨，只有局部淡底渐显。结束手势时提示立即消失。 |
| 数据标签、步骤选择 | 160–180 ms | 数据标签沿用 160 ms，步骤胶囊沿用 180 ms。位置过渡采用现有 OutCubic，起步快、接近目标时减速。连续点选直接改目标。 |
| 已知总量的任务进度 | 200 ms | 从当前绘制值到最新报告值，由一个动画驱动。短任务可以直接进入终态。 |
| 手动收展、B-scan 全屏 | 180–220 ms | 处理工具栏保留 180 ms，通用折叠和全屏保留 220 ms。空间页随三维模式自动展开的附属卡直接就位，将首屏绘制时间留给轨迹。全屏复用当前视图并可由 Esc 中断。 |

**减少动态效果**放在“设置 → 外观与工作区”，提供“跟随系统”（默认）和“减少动态效果”。复用现有 Windows 动画偏好，系统偏好读取失败时用户仍能手动选择。启用后，应用管理的运动直接落到已请求的终态，保留静态选中线、落区边框、进度数字和阶段文字。已打开和延后创建的控件均读取同一偏好。菜单、提示条与其他 Fluent 内置效果按实际入口核验覆盖。[现有动效入口](../../../ui/motion.py) · [设置页](../../../ui/pages/settings_page.py)

设计令牌提供按用途命名的时长，`ui.motion` 统一执行策略。开屏停留时间、提示可读时间和数据预览节流各自由对应组件管理。[时长令牌](../../../ui/design_tokens.py) · [令牌回归](../../../tests/test_design_tokens.py)

## 改动顺序与验收

1. **先改处理工作区的标签和拖放。** 用同一条测线打开三个来源，鼠标和键盘连续切 A → B → C，中途让预览回填。C 的下划线、图像和标签名称最终一致，另一组视口稳定。拖动时在同一落区送入多次移动事件，仅首次进入启动淡入；再跨组、按 Esc、实际松手，各自检查有无残留和最终分组。[工作区回归入口](../../../tests/test_bscan_workspace.py)
2. **再改任务反馈。** 分别验证极短任务、总量未知、取消后仍收到一条进度、失败后立即重新运行。任务行保留可读终态，新任务首条事件前不显示上一项进度。AutoTune 等已有业务专属失败提示的作业按任务 ID 协调通用与专属提示，一次失败只弹一次，详情留在任务记录。逐一计算五种状态在两种主题的文字对比度。[任务事件](../../../ui/coordinator_jobs.py) · [处理反馈](../../../ui/coordinator_processing.py) · [已有中断回归](../../../tests/test_ui_motion_interruption.py)
3. **最后统一面板、弹层和偏好。** 记录工具栏手动宽度，快速收、展、收、展并切页返回，检查最后目标和记忆宽度。在弹层中用键盘打开子菜单、取消并返回入口。分别在 Windows 关闭动画、在应用选择“减少动态效果”，再重复上述操作。在过渡中更改偏好也应立即就位。全屏进出保有原组、轴范围、色阶和另一组的视口。[折叠回归](../../../tests/test_collapsible_motion_policy.py) · [菜单生命周期](../../../tests/test_context_menu_lifecycle.py) · [全屏回归](../../../tests/test_bscan_fullscreen_transition.py)

状态与信号回归交给 GitHub Actions，按提交记录 SHA、运行链接和结果。视觉验收使用 Windows 实窗，检查浅色、深色、窄窗、100%／150%／200% 缩放与跨屏全屏返回。使用同一测线、相同窗口和缩放重复前后操作，分别记录输入到首次可见反馈、最终落位和是否误触发加载。大测线需观察真实数据下的拖动与拾取。
