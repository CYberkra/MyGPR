# MyGPR 第十一阶段：后端验收与代码瘦身报告

## 结论

第十阶段后端与工业测试基线在当前 Linux/Python 3.13 环境中通过复验。使用完整营山六条测线数据执行了冻结哈希校验；工业自动化套件、覆盖率门禁、追踪矩阵、测试分类、重复审计和变异契约均通过。

本轮没有推倒既有架构，而是完成低风险、可量化的代码瘦身与超大模块拆分。运行时 wheel 中不再包含开发脚本，历史处理方法注册表由 1920 行单文件拆为小型兼容门面和四个声明式分组。

## 环境验收

- Python：3.13.5
- 验收模式：后端/无 GUI，`QT_QPA_PLATFORM=offscreen`，`MPLBACKEND=Agg`
- 完整营山资产：`营山测线数据.zip`
- 六条测线：3、6、7、9、L1、X1

当前内部 Python 包镜像无法提供完整锁定依赖，PyWavelets、PyQt6、Hypothesis、Ruff、Mypy 和 PyVista 未能在新建隔离环境中安装。因此，本轮不能替代 Windows GUI、PyWavelets、Ruff/Mypy 或 CUDA 实机验收；发布门禁仍保留这些外部证据要求。

## 自动化验收结果

- 工业套件：49 项通过，0 失败，0 跳过
- 变异契约：3/3 变异被捕获
- 营山完整数据冻结校验：6/6 文件通过
- 关键覆盖率门禁：通过
- 需求/风险追踪：22 项需求、14 项风险，通过
- 测试分类：290 个模块，`misc=0`
- 重复审计：1517 个测试，精确重复组为 0
- 后端、算法注册表和处理执行定向回归：86 项通过，2 项因本机缺少 PyWavelets 主动排除
- 安装后 wheel 后端冒烟：通过

## 本轮优化

### 1. 运行时 wheel 瘦身

开发与验证脚本不再作为生产 wheel 包安装内容。工业测试仍在源码树中运行，但不再暴露一个离开源码树即失效的运行时入口。

| 指标 | 第十阶段 | 第十一阶段 | 变化 |
|---|---:|---:|---:|
| wheel 大小 | 1,671,075 B | 1,269,299 B | -24.0% |
| wheel 文件数 | 501 | 402 | -99 |
| wheel Python 文件 | 494 | 395 | -99 |
| wheel Python 行数 | 149,595 | 114,581 | -35,014 |
| wheel 中 `scripts/` 文件 | 105 | 0 | -105 |

### 2. 处理方法注册表拆分

- `core/methods_registry.py`：1920 行降至 159 行。
- 新增四个声明式方法分组，最大文件 540 行。
- 注册表方法数量、顺序、元数据、公开目录、算法目录和历史可调用对象导出与拆分前一致。
- 超过 1000 行的生产模块：21 降至 20，达到当前减债目标。

### 3. 兼容门面去重

- 18 个重复的 `PythonModule` 转发门面改用统一 `_compat_facade.py`。
- 对 16 个当前可导入门面执行拆分前后导出集合对比，完全一致。
- `PythonModule` 总行数：2542 降至 2369。

### 4. 明确删除无效代码

删除两个无内部调用、无 Schema 所有权、无冻结兼容契约的模块：

- `core/autotune_score_context.py`
- `PythonModule/rpca_placeholder.py`

### 5. 验证环境分层

新增：

- `requirements-test-backend.txt`：无 Qt/VTK 的后端测试环境
- `requirements-test-gui.txt`：桌面 GUI 测试环境

`requirements-dev.txt` 现在组合 GUI 测试配置，避免后端 CI 为验证核心逻辑强制安装 PyQt/PyVista。

## 仍然臃肿的区域

当前完整桌面 wheel 仍包含旧前端和兼容层：

- `ui/`：40,582 行
- `compatibility/`：5,153 行
- `app_qt.py`：95 行

新前端完成切换后，这 45,830 行可整体退出主运行时；按当前规模估算，wheel Python 代码可由 114,581 行进一步降至约 68,751 行。随后再结束 `PythonModule` 兼容窗口，可再减少约 2,369 行。

后端内部下一批高价值对象是：

1. `core/field_report_export.py` 的 79 决策点主函数；
2. `core/sensor_sync.py` 的 51 决策点同步函数；
3. AutoTune 候选规划和细化函数；
4. 剩余 12 个超过 1000 行的类与 124 个超过 100 行的函数。

这些需要针对数值、报告和数据兼容性建立专门基线后逐域拆分，不适合盲目删除或一次性重写。

## 发布判断

本轮结果可以作为新前端合并的后端基线。后端与存储没有发现需要推倒重置的问题。商业正式发布仍需要目标 Windows、完整锁定依赖、PyWavelets、CUDA、GUI、代码签名和硬件在环证据。
