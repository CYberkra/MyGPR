# 处理证据链与数据安全

理解 MyGPR 的处理溯源、故障恢复机制及验证边界。操作步骤见[任务指南](../how-to/index.md)。

## 处理证据链

每次处理（单步或流水线）都产出一份**处理清单（manifest）**，回答四个问题：

1. **输入是什么** —— 输入数据的 SHA-256、来源成果 ID、数据集元数据
2. **做了什么** —— 算法 ID 与版本（`implementation_version`，如 `native-1.0`）、参数（用户参数与运行时参数分开记录）、执行轴（分块/全局）
3. **输出是什么** —— 输出 SHA-256、形状、有限性摘要
4. **何时何人** —— 时间戳、耗时、运行时警告

关键设计：

- **算法单一事实来源**：全部 36 个方法由 `NATIVE_ALGORITHMS` 注册表驱动，GUI、CLI、AutoTune、证据导出走同一实现；输入提取、轴语义和参数仍需通过 GUI/CLI 一致性测试验证。
- **等价性验证**：已登记算法通过参考核对比或 golden 数据回归约束；证据只适用于冻结输入、参数和容差。营山全文件哈希检查需要外部数据，CI 缺少该数据时会跳过，不能计作现场效果验证。
- **不可变性**：处理清单为 `immutable-evidence` 治理域——只追加、不修改；处理成果按分支树组织，不覆盖旧结果。

对交付的意义：报告包里的每个数字都能沿证据链回溯到原始采集数据的精确字节。

## 数据安全模型

### 原子性

关键数组与文档写路径使用“临时文件 → fsync → 原子替换”；SQLite 与 HDF5 依赖事务日志协调，不是跨两种存储的原生 ACID 事务。具体持久性受操作系统和设备影响。

### 事务与恢复

结构性修改（导入、保存成果）使用事务日志：

- **进程崩溃 / 断电**：重新打开项目时按事务日志协调未完成提交；真实断电恢复仍需目标设备验收。
- **磁盘写满（ENOSPC）**：写入失败触发整体回滚——导入不留半成品测线，原始数据容器保持字节级不变（有注入测试钉住此契约）。
- **取消**：长任务随时取消，已产生的临时内容清除。

### 备份的完整性

备份压缩包含 SHA-256 清单，**创建后立即执行恢复式校验**。增量备份记录基准链与逐文件哈希，恢复时合并并逐成员校验——坏档在恢复时报错，而不是交出损坏数据。

### 并发保护

项目目录带进程锁（含宿主与进程启动标记）：第二个进程以写模式打开会提示或只读降级，防止双写损坏。

## 验证边界

现有测试覆盖取消、ENOSPC 注入、提交回滚/前滚和备份校验等路径。真实断电、外接盘断连、长时间大数据运行和现场传感器同步需要单独验收。哈希证明文件身份与完整性，不证明地下目标识别正确，也不替代物理标定。
