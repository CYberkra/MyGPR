# 运行处理与 AutoTune

适用 v0.11.0 源码和已发布安装包；版本与安装验证见[发布说明](../../releases/v0.11.0.md)。

## 选择输入并编排新增步骤

1. 选择测线并激活一个 B-scan 标签。顶部“下次输入”就是本次运行的输入。
2. 点画布上方“待执行”算法链右侧的“＋”，在方法选择器搜索并添加算法；可连续添加。
3. 点击算法节点调参，点“应用”保存。拖动节点调整顺序，或用节点菜单上下移动、复制、
   替换、停用和删除；确认后点“从此结果运行”。

当前有效成果标签可直接续算。选旧结果后运行会在它下面生成新的分支，已有成果保持可用。
顶部算法链只显示准备追加的步骤，不会把上游已完成算法自动再跑一遍。
工具栏“已完成来源”小按钮可展开/收起来源路径，用于返回实际保存的上游结果；
展开不改动当前输入和草稿，点击具体来源才打开对应结果，不执行处理。
原始输入也是普通标签，可关闭、恢复、固定和拖动；增加结果不会自动分屏。
拖标签到画布边缘可拆分对照，拖回另一组标签条可合并。拖动结果标签只调整视图，
拖动算法节点才改变待执行顺序。

测线下拉列表中，单击仍切换当前处理测线；按住某条测线并拖动，可将其原始数据作为
独立对比预览拖入 B 扫。落到画布四边会分屏，落到中心或标签栏会添加标签。
拖动和浏览对比标签不改变处理输入及其草稿；对比标签菜单中的“设为处理输入”才切换输入。
切换处理测线会保留已打开的对比；同一条测线再次拖入会定位已有对比标签。
Esc 或拖到工作区外取消。关闭只关闭视图并释放预览，不删除数据；恢复标签时重新加载。
对比标签和分屏在当前项目会话内保留，切换项目时清除。

Ctrl+W 关闭当前标签，Ctrl+Shift+T 恢复最近关闭，Ctrl+Tab 切换标签；
Shift+F10/Menu 打开当前对象菜单。“项目资源”“处理工具”小图标控制对应侧栏。

## 参数编辑

点击算法节点打开参数弹层；**点“应用”才保存本次弹层改动**，Esc 或关闭丢弃未应用值。
弹层也可启停、上下移动、复制、替换或删除算法。替换成功后选择器关闭；若选择期间
算法链已改变，会提示重新选择目标，避免替换错位置。
展开“处理工具”后也能使用左侧参数表单与 AutoTune；左侧表单改动立即写入所选步骤草稿。
每个项目/测线/数据结果保留独立草稿，切换或关闭标签不丢失。数据修订变化时旧草稿隔离，
不会静默套用到新数据。切换输入或测线时旧弹层关闭，未应用值不会写入新输入。
提交后该输入草稿锁定；其他结果仍可查看或配置。
成功只清除提交源草稿，失败或取消保留草稿。

## 批量处理

批量作业使用 [CLI](无界面批处理.md) 或后端接口；当前处理页围绕一次输入及其新增步骤工作。

## 修改已完成步骤或重建运行

结果菜单“修改此步参数并另建分支”打开它的真实前置输入，仅载入这一方法。
多步运行只保存最终矩阵、没有紧前步骤输入时，此动作禁用。
历史运行菜单“按原输入重新配置本次运行”可载入整次提交配置，仍需显式运行。
替换已有非空草稿会说明目标和步骤；取消保留原输入与草稿，替换后可从草稿菜单恢复备份。
右键本身不切换处理输入；“从此结果继续处理”才主动激活命中结果。

## AutoTune 自动调参

选中一个新增步骤，展开“自动调参”并点“开始调参”：在当前输入上按约束搜索参数。
回包只供原草稿采用；切换输入后不会把结果写到另一份草稿。

- 安全边界内置：所有候选按数据尺度（采样数/道数/时窗/奈奎斯特频率）夹紧，越界候选自动限幅并记录约束警告；异常试验仍需根据失败原因排查。
- 输出：推荐参数、全部试验（含失败试验与原因）、Top-3 候选与偏好排序。
- 证据可导出：编程接口 `mygpr.application.autotune.evidence.export_autotune_evidence` 落盘 JSON（含 body SHA-256 防篡改），供报告附录与溯源。

旧预设档已移除；运行时使用当前显式处理链。

## 处理成果与中间成果

运行完成后结果自动成为**处理成果（Artifact）**：

- 标签和项目资源树显示实际执行的算法，例如“低频漂移校正（Dewow） → 自动增益控制（AGC）”；较长流程显示末步及累计步数，悬停查看全部步骤和参数。继续处理已有成果时累计其已确认的前序流程，自定义成果名称也会保留。
- 保存的流程条可查看每步名称；没有单独保存矩阵的中间步骤不可点击。旧成果缺少可靠来源时显示“处理记录不完整”，不从文件名猜测算法。包络、对比度等显示调整不计入已保存算法。
- 以普通标签打开，可手动分组与原始输入/其他成果对比
- 完整谱系：输入数据、算法、参数、运行时警告全部记入处理清单（SHA-256 证据链，见[原理解释](../explanation/处理证据链与数据安全.md)）
- 开启逐步保存时，中间输出与最终输出均可从来源树/历史打开；只保存最终矩阵时，不显示不存在的内部数据节点
- 中间成果清理会保留被其他成果引用的输入和分支头；显式删除使用后代依赖闭包并确认影响范围，保留兄弟分支

## SEG-Y 导出

任一处理成果可导出为 SEG-Y（float32 大端，行业标准交付格式）：编程接口 `backend.export_artifact_segy(project_id, line_id, artifact_id, destination)`。

## 注意

- 预检与视窗读取使用分块/懒加载；处理是否分块取决于算法和保存中间成果设置。全局算法或默认保存中间成果可能物化完整矩阵，应先查看资源估计。
- 运行中可显式取消；已经成功保存的步骤可能保留，不能假定整次内容全部回滚。
- 用户改变浏览上下文后，完成任务不抢回输入或页面；用“查看新结果”主动打开。
- 预览失败时在对应数据上显示错误，来源菜单可重试；显示设置不改变矩阵或新增数据分支。
