# 数据格式参考

核查日期：2026-10-20。**格式注册表、底层读取器与项目导入向导是三个不同层次**；扩展名出现在文件选择器中不代表向导已接通该格式。

## 当前入口支持范围

| 格式 | 扩展名 | 项目测线导入 | 底层 / 其他入口 |
| --- | --- | --- | --- |
| MyGPR / 矩阵文本 | csv, txt | 直接支持 | CLI；航空堆叠 CSV 提取经纬度、幅值和高度 |
| NumPy | npy, npz | 直接支持二维矩阵 | `core.gpr_io.auto_load_data`；CLI 当前不接此入口 |
| CDUT 采集 / 矩阵 HDF5 | h5, hdf5 | 直接支持 | CLI、采集 API、`auto_load_data` |
| MALÅ | rd3, rd7, rad | 需先转换 | `auto_load_data` 支持有限子集，需同名 RAD |
| ImpulseRadar | iprb, iprh | 需先转换 | `auto_load_data` 支持有限子集，需同名 IPRH |
| SEG-Y | sgy, segy | 需先转换 | `auto_load_data` 支持固定采样数子集 |
| ENVI BSQ | dat, hdr | 需先转换 | `auto_load_data` 支持 BSQ 子集，需 HDR |
| Sensors & Software | dt1, hd | 需先转换 | `auto_load_data` 支持 int16 逐道子集，需 HD |
| GSSI | dzt, dzg | 需先转换 | `auto_load_data` 支持单通道 8/16/32 位 DZT；DZG 不单独解码 |
| gprMax 输出 | out | 需先转换 | 注册表识别；当前 `auto_load_data` 没有 `.out` 解码路由 |

`GPR_FORMAT_SPECS` 的 `native` / `native-subset` 是注册表声明，不是端到端导入验收结论。正式项目入口由 `core.field_import_preview` / `core.field_project_operations` 决定；底层读取路由见 `core.gpr_io.auto_load_data`。

## CDUT 采集 HDF5

- `/traces`: float32，形状为 `(道数, samples_per_trace)`；导入转置为软件的 `(采样点, 道数)`。
- 根属性：`samples_per_trace`、`time_window_ns`、`store_component`（`real`、`mag`、`magnitude` 或远程数据流的 `fdata`）；保留分量原名，不重标为另一种信号。`mag` 与 `magnitude` 都表示幅值，不包含原始相位与正负号。`input_domain`、`signal_domain`、`prefix` / `created`、测次 `acquisition_id` 和存在的模拟数据标记随元数据保留；显式非时域 `signal_domain` 不能作为时域 A-Scan 导入。
- 未声明端点的历史文件沿用 `time_window_ns / samples_per_trace`，时间轴不含时窗右端点；预检提示定量解释前核对采集时间轴。376 道 × 501 点、900 ns 的这种样例导入为 `501×376`，最后采样时刻约 898.204 ns。文件若显式声明布尔属性 `time_axis_endpoint=true`，则使用 `window/(N-1)`，包含右端点；不会仅凭点数或分量推断约定。
- `time_window_ns=0` 表示未知，保留零占位轴并由质检提示，不套用默认时窗。
- `/trace_meta/lon,lat,alt,height` 逐道对齐；NaN 表示传感器缺失，不删除对应雷达道。HDF5 内传感器值优先于可选 JSON sidecar；已有显式同步结果优先于原采集元数据。
- 可选逐道字段 `roll/pitch/yaw`（度）、`ax/ay/az`（g）、`gx/gy/gz`（度/秒）、`timestamp_ms`（采集端 UTC 毫秒）和整数 `trace_id` 一并保留。处理接口映射为 `roll_deg/pitch_deg/yaw_deg`、`accel_*_g`、`angular_rate_*_dps`，并提供 `trace_timestamp_s`（秒）。道号保持整数精度，不以接收时间补造采集时间。
- 已存在的传感器数组必须与雷达道数一致；若有 `committed_trace_count`，它必须与实际道数一致，否则先完成采集或恢复文件再导入。未提供此属性的旧文件仍按原规则读取；计数相等不代表可以跟随仍在写入的文件。
- 文件不提供扫频轴或道间距，不能仅凭 501 点推断 20–170 MHz，也不能把缺少测距时的道序号占位当成米数。
- 采集结束后导入；当前没有跟随活跃写入文件的实时刷新功能。

CDUT 1.1.11 SFCW 主文件已是 ICZT 后的时域数据，`input_domain=frequency` 说明采集输入，不表示应对主矩阵再次做频时变换。
同目录 `<文件名>.sfcw.json` 若存在，必须通过非零测次 UUID、样点数、时窗、存储分量及 ICZT 参数检查；匹配后采用原 Bluestein 的含末点时间轴（501 点、900 ns 的间隔为 1.8 ns）。显式端点属性与原配置冲突时拒绝导入。
配置缺失时不猜测频率轴或端点，主波形仍可导入并提示沿用历史约定；存在但损坏或错测次的配置须核查后再导入，不能静默忽略。
项目导入以分块、可取消方式一并保留 `.sfcw.json` 与可选 `.s21.jsonl`；替换同名测线时不继承旧测次伴随文件。已验证的配置及时间轴随项目保存，重开不依赖外部原路径。
原始 S21 仅检测存在并保留，未校验日志内每条频谱、未重算 ICZT；缺少它不阻断主波形处理。传感器缺失仍保留雷达道和 NaN，完整率不代表 RTK 解状态、同步或物理精度已验收。

`store_component='fdata'` 的远程数据流文件可直接导入波形和逐道快照，预检明确标为“仪器显示采样”。
`fdata` 表示 VNA 显示采样，其物理轴、幅值含义和变换状态仍须结合采集配置确定；文件可读不代表复数 S21 或时域实部已经得到确认。
缺少分量标记的历史采集文件仍拒绝，不能猜测或重标为 `real` / `magnitude` 来绕过检查。
跨仓库数据约定及待对齐项见 [平台对接说明](../../developer/CDUT_PLATFORM_INTEGRATION.md)。

通用二维 HDF5 矩阵保持原有采样点×道方向，不按矩阵长宽猜测转置。HDF5 有层级结构并不代表任意 schema 均受支持。

## MyGPR 处理结果 HDF5

逐步结果 ZIP 中的 `steps/<序号>/data.h5` 和 `raw/data.h5` 使用独立 schema `mygpr.processing_result_hdf5.v1`。
`/matrix` 为 float32、采样点×道；`/distance_axis_m`、`/time_axis_ns`、`/depth_axis_m` 保留成果的已保存轴。
根属性含时窗、介电常数、成果号和来源元数据，导入时不按默认时窗重建已保存轴。时窗为零时仍表示未知。
可选根属性 `dataset_role` 区分 `processing_result`（已保存成果）和 `raw_input`（工程中未处理输入）；旧文件无此属性时仍按原规则读取。
`raw/data.h5` 每包一份，保留打包时原始矩阵和坐标轴，原始采集 CSV/H5 文件不逐字节复制；来源见 `raw/source.json` 和 `manifest.json.raw_input`。
处理步快照的传感器数组未保存时不从原始采集数据推造。参数、分支和可靠直接来源同时见包内 JSON 清单。
本维护源码已接通项目导入和 `load_gpr_dataset`；此前安装的 0.11.1 尚不具备此 schema 的完整轴恢复能力。

## 厂商二进制子集

**RD3/RD7**：`<i2`/`<i4` 连续逐道；RAD 提供 SAMPLES / TIME WINDOW / DISTANCE INTERVAL / LAST_TRACE。

**DT1**：每道 128B 道头 + samples×int16；HD 提供采样和位置单位，ft 自动换算 m。

**DZT**：固定头、单通道 8/16/32 位；无符号幅值按读取器约定转有符号。

**SEG-Y**：3200B 文本头 + 400B 二进制头 + 逐道 240B 道头与样本；仅固定采样数和已支持编码。

**ENVI BSQ**：HDR 声明 samples/lines/bands/data type/interleave/byte order，DAT 保存数组。
