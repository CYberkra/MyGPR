# 数据格式参考

核查日期：2026-10-14。**格式注册表、底层读取器与项目导入向导是三个不同层次**；扩展名出现在文件选择器中不代表向导已接通该格式。

## 当前入口支持范围

| 格式 | 扩展名 | 项目测线导入 | 底层 / 其他入口 |
| --- | --- | --- | --- |
| MyGPR / 矩阵文本 | csv, txt | 直接支持 | CLI；航空堆叠 CSV 提取经纬度、幅值和高度 |
| NumPy | npy, npz | 直接支持二维矩阵 | `core.gpr_io.auto_load_data`；CLI 当前不接此入口 |
| CDUT 采集 / 矩阵 HDF5 | h5, hdf5 | 直接支持 | CLI、采集 API、`auto_load_data` |
| MALÅ | rd3, rd7, rad | 需先转换 | `auto_load_data` 支持有限子集，需同名 RAD |
| ImpulseRadar | iprb, iprh | 需先转换 | `auto_load_data` 支持有限子集，需同名 IPRH |
| SEG-Y | sgy, segy | 需先转换 | `auto_load_data` 支持固定采样数子集 |
| ENVI BSQ | dat, hdr | 需先转换 | `auto_load_data` 支持 BSQ 子集，需 HDR |
| Sensors & Software | dt1, hd | 需先转换 | `auto_load_data` 支持 int16 逐道子集，需 HD |
| GSSI | dzt, dzg | 需先转换 | `auto_load_data` 支持单通道 8/16/32 位 DZT；DZG 不单独解码 |
| gprMax 输出 | out | 需先转换 | 注册表识别；当前 `auto_load_data` 没有 `.out` 解码路由 |

`GPR_FORMAT_SPECS` 的 `native` / `native-subset` 是注册表声明，不是端到端导入验收结论。正式项目入口由 `core.field_import_preview` / `core.field_project_operations` 决定；底层读取路由见 `core.gpr_io.auto_load_data`。

## CDUT 采集 HDF5

- `/traces`: float32，形状为 `(道数, samples_per_trace)`；导入转置为软件的 `(采样点, 道数)`。
- 根属性：`samples_per_trace`、`time_window_ns`、`store_component`（`real` 或 `magnitude`）；`prefix` / `created` 随元数据保留。
- 时间间隔为 `time_window_ns / samples_per_trace`，时间轴不含时窗右端点。376 道 × 501 点、900 ns 的样例导入为 `501×376`，最后采样时刻约 898.204 ns。
- `time_window_ns=0` 表示未知，保留零占位轴并由质检提示，不套用默认时窗。
- `/trace_meta/lon,lat,alt,height` 逐道对齐；NaN 表示传感器缺失，不删除对应雷达道。HDF5 内传感器值优先于可选 JSON sidecar；已有显式同步结果优先于原采集元数据。
- 文件不提供扫频轴或道间距，不能仅凭 501 点推断 20–170 MHz，也不能把缺少测距时的道序号占位当成米数。
- 采集结束后导入；当前没有跟随活跃写入文件的实时刷新功能。

通用二维 HDF5 矩阵保持原有采样点×道方向，不按矩阵长宽猜测转置。HDF5 有层级结构并不代表任意 schema 均受支持。

## 厂商二进制子集

**RD3/RD7**：`<i2`/`<i4` 连续逐道；RAD 提供 SAMPLES / TIME WINDOW / DISTANCE INTERVAL / LAST_TRACE。

**DT1**：每道 128B 道头 + samples×int16；HD 提供采样和位置单位，ft 自动换算 m。

**DZT**：固定头、单通道 8/16/32 位；无符号幅值按读取器约定转有符号。

**SEG-Y**：3200B 文本头 + 400B 二进制头 + 逐道 240B 道头与样本；仅固定采样数和已支持编码。

**ENVI BSQ**：HDR 声明 samples/lines/bands/data type/interleave/byte order，DAT 保存数组。
