# 项目目录与文件位置

## 项目内结构

一个 MyGPR 项目 = 一个目录。导入/处理/标注全部在该目录内完成，可整体拷贝迁移。

```
<项目目录>/
├── project.json                    # 工程清单（身份/坐标系/设置）
├── data/lines/<测线>.h5            # 归一化 GPR 数据（HDF5 分块存储）
├── raw/<测线>/                     # 导入源文件副本 + 导入清单
│   ├── import_manifest.json
│   └── sensors/                    # 传感器同步产物（轨迹/元数据/来源）
├── metadata/                       # 测线元数据、界面标注、解释特征
├── interpretations/                # 标注历史版本
├── exports/                        # 项目导出登记
├── artifacts/                      # 处理成果（分支树）
├── reports/                        # 报告包
├── logs/                           # 项目级操作日志
└── .mygpr.lock                     # 运行锁（勿删）
```

注意：`catalog.sqlite`（成果目录数据库）与 `-wal/-shm` 是混合存储的活跃文件，项目打开时勿手工拷贝单个文件——用[备份功能](../how-to/生成报告与备份.md)（会先 checkpoint 再打包）。

## 用户级位置

| 内容 | 位置 |
|---|---|
| 应用日志 | `~/MyGPR/logs/`（含崩溃转储 `crash-*.json`） |
| 默认备份根 | `~/MyGPR_Backups/<项目名>/`（可用环境变量 `MYGPR_BACKUP_ROOT` 覆盖） |
| 设置 | 用户目录下 `settings.json`（设置页修改） |
| 默认项目根 | `~/Documents/MyGPRProjects/`（设置页可改） |
| 证据导出 | 仓库同级 `MyGPR-Evidence/` 或用户应用数据目录 |

## 日志与诊断

- 操作日志（GUI 右栏与 `logs/field_workbench.log`）记录每次导入/处理/备份的关键动作与耗时。
- 崩溃时自动在 `~/MyGPR/logs/` 写 `crash-*.json` 转储（栈 + 环境），反馈问题时附上。
- 所有长任务在任务中心有完整事件流，可复制报错详情。
