## 1. 安装与启动

环境要求：Python 3.11–3.13；Windows / Linux 均可。

```bash
python -m pip install -r requirements-core.txt   # 后端依赖（精确钉版）
python -m pip install -r requirements-gui.txt    # 图形界面依赖
python app_qt.py                                  # 启动桌面应用
```

首次启动会显示约 600ms 开屏画面，随后进入主窗口；后端在后台初始化，右下日志面板出现「后端初始化完成」即可开始使用。

无图形界面的环境（服务器 / SSH）可以用命令行批处理：

```bash
python cli_batch.py validate --config myjobs.json   # 校验作业配置
python cli_batch.py run --config myjobs.json        # 执行批处理
python backend_smoke.py --skip-autotune             # 后端自检
```

## 3. 支持的数据格式（v0.9.37 收敛批次起全部可直读）

| 格式 | 扩展名 | 必需伴随文件 | 说明 |
|---|---|---|---|
| MyGPR / 矩阵 CSV | `.csv` `.txt` | — | 二维矩阵或无人机堆叠 CSV（经纬度+幅值+高度） |
| MALÅ RD3/RD7 | `.rd3` `.rd7` | 同名 `.rad` | 16/32 位逐道数据 |
| Sensors & Software DT1 | `.dt1` | 同名 `.hd` | 文本头 + int16 逐道；`.hd` 中位置为 ft 时自动换算 m |
| GSSI DZT | `.dzt` | —（`.dzg` 可选） | 8/16/32 位单通道 profile |
| Geotech OKO | `.gpr` `.gpr2` | — | OKO-2 二进制（俄语头字段自动解码） |
| SEG-Y | `.sgy` `.segy` | — | 固定采样数、int16/int32/float32 大端 profile |
| ENVI BSQ | `.dat` | 同名 `.hdr` | 二维/三维 band-sequential 数组 |
| ImpulseRadar | `.iprb` | 同名 `.iprh` | 16/32 位逐道 |
| gprMax 输出 | `.out` | 同目录 `.in` | 仿真数据；`.in` 补充道间距 |
| NumPy | `.npy` `.npz` | — | 必须是二维 B-scan 矩阵 |

导入时先做**预检**：主页/项目页选择文件后会显示格式、矩阵规模、是否含轨迹，确认后再导入。导入过程中取消或磁盘写入失败都会自动回滚，不会留下半成品项目。

## 4. 典型工作流（图形界面）

1. **新建项目**：主页 →「新建项目」，选择目录与项目名；如已知坐标系建议在项目信息里设置（如 `CGCS2000 / 3-degree GK zone 36`），空间成果需要它。
2. **导入测线**：项目页 →「导入测线」，按上表选文件 → 预检 → 导入。无人机 CSV 可同时提供 RTK/IMU 侧车文件做传感器同步（项目页 →「传感器同步」），同步后自动生成轨迹文件。
3. **处理**：处理页从方法库双击添加算法 → 右侧调参（或点「开始调参」让 AutoTune 自动搜索）→「运行处理链」。结果自动成为处理成果并在预览中与原始数据对比。所有执行参数与结果都会记入处理清单（含 SHA-256 证据链）。
4. **解释**：解释页打开标注会话 → 在 B-Scan 上点击拾取基覆界面 → 自动追踪/平滑 → 确认后保存。界面标注是空间成果的前置条件。
5. **成果**：
   - 「生成空间成果」：把界面标注与轨迹合成为带版本号的空间成果（可多版本管理）；
   - 「生成报告包」：一键产出 PDF/HTML/Excel 报告 + 图件 + 文件审计 + 校验和，交付目录自包含；
   - 「备份」：全量或增量备份（见第 6 节）。
6. **任务中心**：所有耗时操作都在后台执行，任务页可查看进度、取消或清理历史。

## 5. 无界面 / 批处理工作流

服务器或自动化场景通过 `MyGPRBackend` 或 `cli_batch.py` 完成同样的事：

```json
{
  "jobs": [
    {
      "id": "demo-line",
      "input": "data/Line3.csv",
      "recommended_profile": "robust_imaging"
    }
  ]
}
```

```bash
python cli_batch.py run --config myjobs.json
```

- `recommended_profile` 支持 `robust_imaging`、`high_quality_uav_gpr`、`hankel_denoise`、`wavelet_2d_denoise`、`motion_compensation_v1` 等 10 个预设档，或直接给 `methods` 列表逐算法指定参数。
- 每步输出 CSV + PNG 落盘，`final.csv` 为最终结果。
- 报告 / 空间成果 / 备份也可以编程触发（`submit_project_report`、`submit_spatial_result`、`build_georeference_3d`、`submit_project_backup`），全部走任务系统，与 GUI 同一条路径。

## 6. 备份、恢复与数据安全

- **备份**：成果页「备份」或 `submit_project_backup`。备份是带 SHA-256 清单的压缩包，创建后立即做恢复式校验。`incremental=True`（编程接口）只打包相对上一次备份变化的文件，恢复时自动合并基准链。
- **外置设备**：勾选「必须使用外部设备」时，备份目标与项目不在同一物理磁盘才会执行——正式灾难恢复建议开启。
- **保留策略**：编程接口支持 `retention_keep=N` 自动清理最旧档案；GUI 手动管理备份目录即可。
- **崩溃安全**：所有写入都走"临时文件 + 原子替换"；进程中断或断电后重新打开项目会自动回滚未完成事务；磁盘写满时导入/保存会整体回滚，原始数据保持不变。
- 恢复：成果页「恢复」选择备份包，恢复为新项目目录（不覆盖原项目）。

## 7. 故障排查

| 现象 | 处置 |
|---|---|
| 导入报"格式不支持" | 检查扩展名与伴随文件（RD3 要 `.rad`、DT1 要 `.hd`、ENVI 要 `.hdr`）；预检面板会显示识别到的格式 |
| 导入报"文件截断/数据不足" | CSV 头声明的采样点×道数大于实际数据行；用设备软件重新导出 |
| 处理结果全屏异常值 | 检查介电常数 / 时窗设置是否与采集一致；AutoTune 的参数约束会按数据尺度自动限幅并给出警告 |
| 空间成果预检失败 | 每条测线需要：轨迹文件（传感器同步生成）+ 已确认的界面标注；预检错误会逐条列出 |
| 备份报"必须使用外部设备" | 备份目标与项目在同一物理磁盘；换移动硬盘或取消勾选 |
| 日志位置 | `~/MyGPR/logs/`；项目级操作日志在项目目录 `logs/` 内 |

## 8. 名词速查

- **测线（Line）**：一次连续采集得到的 B-scan 数据与轨迹，项目内的基本组织单位。
- **处理成果（Artifact）**：某测线经过一步或多步处理后的数据版本，带完整谱系。
- **AutoTune**：自动参数推荐。在当前数据上按安全约束搜索参数空间，输出推荐值与全部试验证据。
- **基覆界面标注**：在 B-scan 上标记的覆盖层底界面曲线，空间成果与报告的主要解释依据。
- **空间成果**：轨迹 + 界面标注合成的地理定位成果，按版本管理。
