# MyGPR v0.9.28 Production Hardening V1.9

日期：2026-07-14

## 本轮目标

在五页业务闭环和 V1.8 模块联动基础上，补齐发布前的工程引用一致性、异常退出恢复标记、大文件取消清理和生产化验证证据。五页布局与视觉基线不做破坏性修改。

## 核心改动

### 1. 五页工程一致性审计

新增 `core/project_integrity.py`，检查以下引用链：

- 测线 → 原始数据 / 标准化 GPR / RTK 轨迹；
- 处理版本 → 数据、参数和 manifest；
- 标注版本 → 明确处理来源；
- 空间成果 → 测线、处理、标注和正式成果文件；
- 报告 → 空间成果、报告目录和封印；
- 工作区上下文 → 当前测线、处理来源、标注、空间成果和报告；
- 当前空间/报告索引；
- 遗留 staging/tmp 项。

审计结果写入：

```text
metadata/project_integrity.json
```

安全修复只处理工作区指针和当前版本索引，不改写、删除或覆盖正式处理、标注、空间和报告成果。

### 2. 异常退出标记与恢复

新增 `core/project_runtime_guard.py`：

- 打开项目时写入 `state=open`；
- 页面切换和跨模块跳转时更新 checkpoint；
- 正常关闭时写入 `state=closed`；
- 再次打开时若发现上次会话仍为 open，立即执行工程引用与恢复点检查。

运行标记位于：

```text
metadata/runtime_session.json
```

### 3. 取消任务清理

修复 `copy_file_chunked()`：复制过程取消或失败时立即删除截断目标文件，防止残片后续被误判为有效源数据。

### 4. UI 入口与模块联动

- 项目管理页“更多”菜单增加“工程一致性检查”；
- “存储与备份”面板增加同一入口；
- 检查通过任务中心执行，结果通过统一状态区反馈；
- 处理 → 标注 → 空间 → 报告的具体对象传递保持不变；
- 每次跨模块跳转同步写入运行 checkpoint。
